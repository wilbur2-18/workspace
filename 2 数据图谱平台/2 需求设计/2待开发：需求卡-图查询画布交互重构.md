# 图查询画布交互重构

**产品**：数据图谱平台  
**状态**：待开发  
**更新**：2026-05-19  
**关联材料**：`1 需求池/20260430-图查询v1优化需求.md`、`1 需求池/数据图谱平台-初步页面功能结构.md`、`2 需求设计/数据图谱平台 20260518/demo.html`

---

## 1. 需求背景

当前图查询画布已经具备历史查询、画布展示、节点/边详情、显示控制、分析与助手等基础能力，但各区域的职责仍然偏混合：用户进入画布后，需要先判断这张图从哪里来、当前查询条件是什么、图上哪些对象可以继续操作，以及右侧面板当前是在看详情还是做操作配置。

本次优化重点是把图查询画布从“单一图形展示区”调整为“查询条件 - 图谱画布 - 操作面板”的横向分析流，让用户按照从左到右的顺序完成关系核查：先理解查询条件，再查看图谱结果，最后针对选中的节点、边或聚合对象查看明细、配置操作或继续分析。

---

## 2. 目标场景

业务用户进入某次图查询结果后，可以先在画布左侧确认本次查询基于哪个图谱、用了什么查询方式、查询对象和过滤条件是什么；随后在中间画布查看关系结构、聚合结果或列表明细；当选中节点、边或聚合组时，可以通过底部对象操作触发业务动作，并在右侧共用操作面板中查看详情、配置拓展、查看来源或执行路径分析。

---

## 3. 本次做什么

### 3.1 画布采用横向查询流结构

画布主区域按“查询条件 - 图谱画布 - 操作面板”组织，形成清晰的从左到右工作流。

| 区域 | 页面定位 | 主要内容 | 交互规则 |
| --- | --- | --- | --- |
| 左侧：当前查询 | 解释当前图从哪里来、怎么查出来 | 底层图谱、查询方式、查询对象、查询步数、关系类型、过滤条件、查询状态、结果规模 | 修改条件或重新查询后，中间图谱结果刷新；不承载节点详情 |
| 中间：图谱画布 | 展示本次查询形成的小图结果 | 节点、边、聚合组、路径高亮、画布/列表双模式 | 选中节点、边或聚合组后，驱动底部对象操作和右侧操作面板变化 |
| 右侧：操作面板 | 承载详情查看、操作配置和结果解释 | 节点详情、边详情、聚合组详情、拓展配置、路径分析配置、来源证据、显示/过滤配置 | 支持展开、收起和切换面板内容；同一时间聚焦一个对象或一个操作 |

说明：

- 左侧“当前查询”是画布的一部分，不作为独立管理侧栏。
- 中间画布默认展示本次查询的小图结果，不直接铺开底层全量图谱。
- 右侧不固定为详情栏，而是当前对象或当前操作的共用浮层。

### 3.2 左侧“当前查询”信息

左侧区域用于让用户快速理解当前画布结果的查询上下文。

| 信息项 | 展示内容 | 操作 |
| --- | --- | --- |
| 底层图谱 | 图谱名称、权限状态、数据范围摘要 | 查看图谱详情 |
| 查询方式 | 实体查询、路径分析、模板查询、查询语句等 | 修改查询方式时回到查询配置 |
| 查询对象 | 当前主体、起点/终点、模板参数等 | 修改查询条件 |
| 查询范围 | 查询步数、关系类型、方向、过滤条件 | 重新查询 |
| 结果状态 | 原始结果、已过滤、已聚合、已隐藏等 | 恢复默认显示 |
| 结果规模 | 节点数、关系数、聚合组数 | 与画布/列表结果保持一致 |

说明：

- “当前查询”默认展示摘要信息，避免占用过多画布空间。
- 修改查询条件时，应明确提示会刷新当前图谱结果。
- 历史查询可以作为左侧的次级入口，但不替代当前查询说明。

### 3.3 顶部工具条：图本身操作

顶部工具条只放与业务对象无关的图操作，处理“这张图如何被查看和操作”。

| 操作类型 | 具体操作 | 规则 |
| --- | --- | --- |
| 视角操作 | 选择、拖拽、放大、缩小、适配画布、居中显示 | 不改变查询结果数据，只改变画布视角 |
| 布局操作 | 布局切换、自动布局、清除样式 | 只影响节点和边的展示位置或样式 |
| 历史操作 | 撤销、重做 | 作用于本次画布操作，不回退底层图谱数据 |
| 结果操作 | 保存、导出、全屏 | 保存为历史小图或导出当前查询结果 |

说明：

- 顶部工具条不放“拓展节点、查看来源、路径分析”等业务对象操作。
- 常用操作直接展示，低频操作可以进入“更多”菜单，避免工具条过长。

### 3.4 底部工具条：实体与边相关操作

底部工具条随当前选中对象变化，处理“当前节点、边或聚合组还能做什么”。

| 当前选中对象 | 底部可用操作 | 操作后反馈 |
| --- | --- | --- |
| 未选中对象 | 框选、清空选择、打开分析、AI 助手 | 右侧操作面板可保持收起或展示通用分析入口 |
| 节点 | 查看详情、拓展、条件拓展、设为中心、查路径、查看邻居、隐藏、从本次结果删除 | 需要配置的操作在右侧操作面板展开；删除仅影响本次结果 |
| 边 | 查看关系详情、查看来源、高亮两端节点、隐藏关系、从本次结果删除 | 查看来源时右侧展示证据或来源说明 |
| 聚合组 | 展开聚合、按类型拆分、只看该组、导出明细 | 展开后画布展示组内对象；右侧展示聚合口径和明细 |

说明：

- 底部工具条不放缩放、布局、导出图片等图本身操作。
- 选中对象变化后，底部工具条应同步更新，避免出现不可执行或不相关操作。
- 删除、隐藏均默认只作用于本次查询结果，不删除底层原始图谱数据。

### 3.5 右侧共用操作面板

右侧作为可展开、可收起的共用浮层，既承载对象详情，也承载操作配置。

| 触发方式 | 右侧面板内容 | 规则 |
| --- | --- | --- |
| 点击节点 | 节点详情 | 展示节点属性、实体类型、来源摘要和可继续操作入口 |
| 点击边 | 关系详情 | 展示关系类型、起点/终点、属性、来源摘要 |
| 点击聚合组 | 聚合组详情 | 展示聚合口径、组内数量、可展开明细 |
| 点击条件拓展 | 条件拓展配置 | 配置拓展层级、关系类型、方向、过滤条件 |
| 点击查路径 | 路径分析配置 | 配置目标节点、路径类型、最大跳数 |
| 点击查看来源 | 来源证据 | 展示该节点或关系的来源数据、表/字段或证据说明 |
| 点击显示/过滤配置 | 显示与过滤配置 | 配置实体类型、关系类型、渲染字段、隐藏对象恢复 |

说明：

- 右侧面板同一时间只聚焦一个对象或一个操作。
- 右侧面板可收起，收起后画布区域扩大。
- 从底部操作进入配置页时，应保留当前选中对象，方便用户返回详情。

### 3.6 图谱/列表双模式与聚合展示

画布结果支持图谱模式与列表模式，并保留聚合展示能力。

| 能力 | 规则 |
| --- | --- |
| 图谱模式 | 用于查看关系结构、路径、邻居和聚合组 |
| 列表模式 | 用于核查节点、边和聚合明细；点击列表行可反向定位画布对象 |
| 同类关系聚合 | 当同一组对象之间存在多条同类关系时，可默认聚合展示，并支持展开 |
| 多实体聚合 | 当同类实体数量过多时，可按类型、风险等级或查询口径聚合展示，并支持展开 |

说明：

- 聚合不是隐藏数据，而是降低首屏复杂度。
- 聚合组必须说明聚合口径和组内数量。
- 展开聚合后，用户应能恢复到聚合展示。

---

## 4. 本次不做什么

1. 不重做后端图查询、图计算或图谱存储能力，优先复用现有查询能力。
2. 不扩展图管理、本体建模、数据接入和权限管理流程。
3. 不改变底层图谱数据，不提供对原始节点或关系的真实删除能力。
4. 不把右侧面板拆成多个固定侧栏，本次统一为一个共用操作面板。
5. 不新增复杂个性化配置，例如跨用户记忆工具条顺序、跨设备同步面板布局。
6. 不把 AI 助手作为主流程，本次只作为可进入的辅助分析入口。

---

## 5. 验收口径

1. 用户进入图查询画布后，可以按从左到右看到“当前查询、图谱画布、操作面板”三段式结构。
2. 左侧“当前查询”可以展示底层图谱、查询方式、查询对象、查询范围、结果状态和结果规模，且结果规模与中间画布/列表一致。
3. 顶部工具条只包含选择、拖拽、缩放、适配、布局、撤销、重做、保存、导出、全屏等图本身操作，不出现节点拓展、路径分析、查看来源等业务对象操作。
4. 当用户选中节点、边、聚合组或取消选择时，底部工具条展示的操作应随对象类型变化。
5. 用户点击底部“条件拓展、查路径、查看来源”等操作后，右侧操作面板可以展开并切换到对应配置或说明内容。
6. 用户点击节点、边或聚合组后，右侧操作面板可以展示对应详情，并保留返回当前对象相关操作的入口。
7. 用户收起右侧操作面板后，中间画布可获得更大展示空间；再次触发对象或配置操作时，右侧面板可重新展开。
8. 图谱模式与列表模式展示同一批查询结果；在列表中点击节点或关系行时，可以定位并选中画布中的对应对象。
9. 同类关系或多实体聚合展示时，用户可以看到聚合口径和组内数量，并能展开查看明细后恢复聚合展示。
10. 隐藏或删除节点/边时，界面明确提示仅影响本次查询结果，不删除底层原始图谱数据。

## 关键决策

| 决策点 | 结论 | 原因 |
| --- | --- | --- |
| 画布主结构 | 采用“查询条件 - 图谱画布 - 操作面板”的横向流向 | 符合用户从理解查询、查看结果到处理对象的自然核查路径 |
| 操作分类 | 顶部放图本身操作，底部放实体/边/聚合组相关操作 | 减少工具混杂，降低业务用户判断成本 |
| 右侧区域定位 | 右侧不是固定详情栏，而是共用操作面板 | 同时承载详情、来源、拓展配置、路径配置和显示/过滤配置 |
| 查询上下文命名 | 界面建议使用“当前查询”，文档可称为查询上下文 | “当前查询”更贴近业务用户语言 |
