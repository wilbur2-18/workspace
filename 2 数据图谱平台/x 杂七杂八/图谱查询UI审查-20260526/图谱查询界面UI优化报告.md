# 数据图谱平台 · 图谱查询 UI 界面优化报告

**审查对象**：`2 需求设计/数据图谱平台 20260520/`  
**审查范围**：L1 图谱查询首页 + L2 图谱画布工作台（画布 / 列表 / 查询范围左栏 / 顶栏 Ribbon / 底栏图例 / 右侧操作面板）  
**审查方式**：代码结构审读 + 浏览器实机走查（1440×900 量级视口）+ 与关联需求卡对照  
**审查日期**：2026-05-26

---

## 一、执行摘要

### 总体评价：**B+（工程完成度高，体验尚未「产品级收敛」）**

原型在**设计系统对齐、组件完整度、无障碍标注**上明显优于一般内部 Demo，L1→L2 的主路径可跑通，画布 Session / 步骤时间轴的方向也与需求卡一致。

但当前界面存在三类核心 UX 债务：

1. **垂直空间被多层 chrome 挤压**——顶栏 Ribbon（约 72px）+ 查询范围左栏 + 底栏图例 + 右侧浮层，画布有效可视区不足 55%，与「图谱研判」主任务不匹配。
2. **工具栏信息架构尚未闭环**——需求卡中的「类型筛选 + 查找定位 + 顶栏显示筛选」在 UI 上尚未形成清晰入口，用户只能依赖底栏图例 chip 和「高级筛选」弹窗，**改口径 vs 改显示** 的边界对用户仍不直观。
3. **文案与控件语义存在「专业感损耗」**——如「两个都」「方向边」「本人」「用有电话」等，会在审计/研判场景下直接伤害信任感。

### 优化目标建议

> 让用户在 3 秒内回答三个问题：**我在查什么 → 我看到了什么 → 我接下来能做什么**。

## 二、宏观层：信息架构与页面结构

### 2.1 L1 图谱查询首页

**现有结构**

```text
顶栏导航
└─ Hero 区：图谱标题 + 切换 + 规模统计
   └─ 快捷查询（Segmented + 表单 + 高级面板）
└─ 双栏：模板查询（2/3）| 历史查询（1/3）
```

**优点**

- 「先查再进画布」的路径清晰，Hero 查询区视觉焦点明确。
- 模板 / 历史双栏符合「发起新查询 vs 续看旧结果」两类意图。
- 模板卡片 glass + hover 露出「查询」按钮，探索感较好。

**问题**

| 编号 | 问题 | 影响 |
| --- | --- | --- |
| M-L1-01 | Hero 区同时承担「图谱上下文 + 查询配置 + 统计展示」，首屏信息层级偏平 | 新用户不知先看标题还是先看表单 |
| M-L1-02 | 「高级查询」使用 Switch 视觉，但实际是展开/折叠，不是即时生效开关 | 错误心智模型，易误以为开关即生效 |
| M-L1-03 | 「清空」浮在表单区右上角，与字段组无视觉从属 | 误触风险高，且不像表单内操作 |
| M-L1-04 | 模板卡片「查询」按钮默认隐藏（hover 才出现） | 可发现性差，触屏/键盘用户几乎不可见 |
| M-L1-05 | 历史列表仅名称 + 日期，缺少查询方式/结果规模 | 回溯成本高，难以区分相似历史 |
| M-L1-06 | 实体 128 万 / 边 420 万与表单字段同处一屏，统计未形成独立「图谱概览」块 | 数字冲击力被稀释 |

**结构优化建议**

```text
[图谱上下文条]  名称 · 切换 · 权限 · 规模（独立轻量 stat strip）
[查询发起区]    Tab：实体 | 路径 | 语句
                主字段一行（≤4 项）+ 主 CTA 固定右对齐
                高级条件 → 可折叠面板（用 Chevron，不用 Switch）
[发现区]        模板（主） + 历史（辅，可切 Tab 而非固定 2:1 分栏）
```

### 2.2 L2 图谱画布工作台

**现有结构（五层嵌套）**

```text
工作台顶栏（返回 / 左 rail 折叠 / 保存撤销 / 开始·分析 Tab）
├─ 左 rail：模板查询 + 历史查询（默认收起）
├─ 中央画布区
│   ├─ Ribbon 工具栏（视图 / 筛选 / 显示 / 导出）
│   ├─ 查询范围左栏（Session 摘要 + 步骤时间轴）
│   ├─ 画布 / 列表
│   ├─ 底栏图例 / 节点操作条
│   └─ 右侧浮层（样式 / 分析 / AI 对话 Tab）
```

**优点**

- 「查询范围 → 结果 → 操作」横向流已基本成型，符合需求卡方向。
- 左 rail 与画布内左栏职责分离（发起 Session vs 管理 Session 内步骤）方向正确。
- 画布 / 列表模式切换、布局 picker、视口控件分组合理。

**问题**

| 编号 | 问题 | 影响 |
| --- | --- | --- |
| M-L2-01 | **双左栏**（rail + 查询范围）+ 顶栏 + 底栏 + 右栏，五层 chrome 同屏 | 图谱可视面积过小，密集图几乎不可读 |
| M-L2-02 | 进入画布时左 rail 默认收起，但模板/历史入口在 rail 内 | 用户不知去哪「加步骤 / 换历史」 |
| M-L2-03 | 顶栏「开始 / 分析」Tab 语义模糊，与「图谱查询」模块名不对齐 | 用户不确定「分析」是否离开当前 Session |
| M-L2-04 | 右侧默认打开「对话」Tab，而非对象详情或样式 | AI 抢主舞台，研判主流程被边缘化 |
| M-L2-05 | 底栏图例在 14+ 类型时横向溢出，需滚动才能看全 | 类型筛选主入口应在顶栏，不应依赖底栏 |
| M-L2-06 | 列表模式 `padding-right: 354px` 硬编码耦合右栏宽度 | 折叠右栏后留白，响应式脆弱 |

**结构优化建议**

采用 **「一主两辅 + 渐进披露」**：

| 区域 | 职责 | 默认状态 |
| --- | --- | --- |
| 主舞台 | 画布 / 列表 | 始终最大化 |
| 左：查询范围 | Session 步骤、口径 | 默认展开，可一键收起 |
| 右：上下文面板 | 详情 / 样式 / 分析（AI 降为子 Tab） | 默认关闭，选中对象后自动打开 |
| 顶栏 | 视图 + **显示筛选** + 导出 | 单行 48px，去掉 cluster caption |
| 底栏 | 仅「选中对象操作」；未选中时隐藏或 1 行摘要 | 不与类型筛选混用 |
| 左 rail | 发起查询 / 历史 | 改为顶栏「新建查询」入口 + 抽屉，而非常驻第三栏 |

## 三、中观层：布局、层级与视觉节奏

### 3.1 垂直空间预算（实测估算）

以 900px 内容高度为例：

| 占用项 | 约高度 | 占比 |
| --- | --- | --- |
| 全局顶栏 | 56px | 6% |
| 工作台顶栏 | 48px | 5% |
| Ribbon 工具栏 | 72px | 8% |
| 查询范围左栏头 | 80px+ | 9% |
| 底栏图例 | 48–56px | 6% |
| **画布净高** | **~590px** | **~65%** |

对 64 节点 / 112 边的密集图，65% 净高仍显不足；再叠加右侧 340px 浮层，画布水平也被吃掉约 24%。

**建议**

- Ribbon 从 **72px 双行（图标 + caption）** 收敛为 **48px 单行**，caption 改 tooltip。
- 查询范围左栏摘要区压缩为 **2 行 KPI + 1 行显示状态**，详情进折叠。
- 底栏图例在未选中时 **不常驻**；类型筛选上移到顶栏「筛选」cluster。

### 3.2 横向栅格与对齐

**L1**

- 快捷表单字段水平排列在宽屏下合理，但 **1280px 以下** 易换行混乱；建议 `@media` 改为 2 行网格：字段区 + CTA 区。
- 双栏 `2fr : 1fr` 固定比在 ultrawide 下历史栏过窄；建议最小宽度 320px + 可拖拽分割。

**L2**

- 查询范围左栏与画布之间缺明确 **8px 槽 + 1px 分隔**，边界靠背景色差区分，弱。
- 列表双表模式下，上下表头样式一致，缺 **「节点 / 关系」色条或图标** 区分，扫视成本高。

### 3.3 视觉层级

**做得好的**

- 主色 `--ds-c-primary` 使用克制，active 态清晰。
- 步骤卡 `is-focused` 蓝色描边有效传达当前步骤。
- 模板卡片 icon 容器统一 40px，节奏稳定。

**需改进**

| 编号 | 现象 | 建议 |
| --- | --- | --- |
| V-01 | 多处 `font-weight: 650`（非 token 字阶） | 统一为 500（标题）/ 600（强调数字） |
| V-02 | 筛选 tag 使用 `11px` | 回升至 12px micro，避免「补丁感」 |
| V-03 | Ribbon 按钮 48px vs 表单控件 32px | 工作台内统一 **32px 控件高 / 40px 触控热区** |
| V-04 | 「查询范围」kicker 与标题字号差仅 2px | kicker 改 12px + uppercase / 字间距，标题 16/500 |
| V-05 | 底栏 chip `em` 计数与类型名同权重 | 计数改 `--ds-text-3`，类型名保持 `--ds-text-1` |

## 四、微观层：组件与像素级审查

### 4.1 L1 快捷查询区

| 组件 | 问题 | 优化 |
| --- | --- | --- |
| Segmented（实体/路径/语句） | 「路径分析」与 L2「路径查询」命名不一致 | 全站统一为「路径查询」 |
| 关系方向 Segmented | 文案「两个都 / 在 / 出去」不专业 | →「双向 / 入边 / 出边」 |
| 路径方向 | 「本人」语义不明 | →「不限 / 正向 / 逆向」 |
| 高级面板 | 与主表单视觉断层，缺「高级条件」小标题 | 加 1px 顶部分割 + 12px 上内边距 |
| 主 CTA | 「快捷查询」与模板区「查询」重复 | L1 统一为 **「开始查询」** |
| 权限提示 | 仅一行小字，禁用时 CTA 灰掉但原因不够显眼 | CTA 旁加 tooltip + 链到权限说明 |

### 4.2 L2 Ribbon 工具栏

**现状 cluster**：视图 | 筛选 | 显示 | 快照与下载

| 问题 | 细节 |
| --- | --- |
| 筛选 cluster 仅「高级筛选」一个入口 | 需求卡要求的 **实体类型 / 关系类型多选** 未在顶栏呈现 |
| 「显示」cluster 含 5 个按钮 | 「全部展开/收起」与单个 toggle 功能重叠，占宽 |
| 布局 picker 卡片信息量大 | 小预览 + 双行文字在 48px 按钮内偏挤 |
| 缺「查找定位」 | 密集图无法 Ctrl+F 式定位，研判效率低 |

**建议顶栏筛选 cluster 结构**

```text
[实体类型 ▼] [关系类型 ▼] [高级筛选] [查找 ⌘F]
              ↑ 多选 dropdown    ↑ 输入即高亮，不缩集合
```

### 4.3 查询范围左栏（步骤时间轴）

**优点**

- 步骤 checkbox 控制「纳入显示」符合「改口径」定义。
- 本步节点/关系计数、过滤摘要、操作按钮齐全。

**问题**

| 编号 | 问题 |
| --- | --- |
| S-01 | 单步骤卡 **4 个并列小按钮**（重新执行 / 更换模板 / 存为模板 / 删除），视觉噪声高 |
| S-02 | 「⋯ 更多操作」与点击卡片聚焦重复 |
| S-03 | 原生 checkbox 与 Ant Design 体系不一致 |
| S-04 | 「添加查询步骤」与「拓展/路径等操作」分两入口，层级不清 |
| S-05 | 多步骤时卡片高度大，时间轴缺 **缩略态**（仅显示序号 + 模板名 + 计数） |

**建议**

- 步骤卡默认 **紧凑态**；聚焦后展开操作区。
- 操作收敛为：**主操作 1 个（重新执行）+ 更多 ▼**。
- checkbox 换 Ant `a-checkbox`，与全站一致。

### 4.4 画布与底栏图例

| 问题 | 优化 |
| --- | --- |
| 64 节点图标签重叠严重 | 默认开启「聚合 / 简化标签」或按缩放级别隐藏边标签 |
| 选中态仅靠边框/大小，对比不足 | 加 2px 外发光环 + 关联边高亮 |
| 视口控件浮在右下，与图例条相邻 | 合并为 **右下角工具栈**，统一 32px 圆形按钮 |
| 图例 14 个 chip 横向滚动 | 顶栏承担筛选；底栏仅保留 **已隐藏 N 类 · 恢复** |
| 选中节点后底栏切为 7 个操作按钮 | 方向正确，但应 **固定高度 56px**，避免布局跳动 |

### 4.5 列表模式

| 问题 | 优化 |
| --- | --- |
| 双表上下分割，关系表可视行数少 | 默认「双表」改 **Tab 切换** 或 **可拖拽分割条** |
| 表头 filter 与高级筛选关系有 hint，但入口隐蔽 | 表头 filter icon 激活态与顶栏 advanced strip 联动高亮 |
| 行点击与画布选中联动不明确 | 点击行 → 画布居中 + 右栏详情，双向同步 |
| 右栏占位 354px 固定 | 改 flex 布局，右栏 `position: absolute` 覆盖而非挤占 |

### 4.6 右侧操作面板

| 问题 | 优化 |
| --- | --- |
| 默认 Tab 为「对话」 | 改为 **无选中时关闭**；选中节点打开「详情」 |
| Tab 过多（对话 / 样式 / 各类分析） | 分析类收进「分析 ▼」下拉，避免 tab rail 溢出 |
| AI 回复区占画布上方浮层感强 | 对话改为 **480px 抽屉**，不覆盖图谱中心 |
| 样式面板表格三列对齐良好 | 保持；颜色 picker 热区可加大至 28px |

## 五、交互与任务流

### 5.1 核心任务链走查

| 任务 | 当前步数 | 摩擦点 |
| --- | --- | --- |
| 从首页发起实体查询 | 3 步 | 较好 |
| 打开历史小图继续研判 | 2 步 | 较好 |
| 在 Session 内加第二步模板查询 | ≥4 步 | 左 rail 默认收起；add step 入口深 |
| 隐藏某类关系后导出 | ≥3 步 | 需到底栏找 chip，非顶栏 |
| 选中节点看详情 | 2 步 | 底栏有「详情」，但右栏不一定自动打开 |
| 列表核查后回到画布定位 | 缺联动 | 列表行点击未强调画布反馈 |

### 5.2 状态反馈

- 保存 / 撤销 / 重做目前为 toast 演示，**无真实 disabled / 历史栈提示** → 建议至少做按钮 disabled 态。
- 重新执行步骤、删除后续步骤等高风险操作，**缺确认对话框**。
- 高级筛选 strip 出现/消失会引发布局跳动，建议 **固定高度占位或 slide-down 动画**。

## 八、优先级优化路线图

### P0 — 1–2 周（体验止损，改动可控）

1. 全文案专业度修正（上表）
2. Ribbon 高度 72→48px，去掉 cluster caption
3. 模板卡片「查询」按钮改为 **常显** 或 hover + 常显 ghost 态
4. 「高级查询」Switch 改 **Chevron 折叠**
5. 进入画布时 **不默认打开 AI 对话**；选中对象再开详情
6. 底栏图例超 8 项时 **折叠为「+N」**，主筛选上移顶栏（可先做多选 dropdown）

### P1 — 2–4 周（结构收敛）

1. 顶栏补齐 **实体/关系类型筛选 + 查找定位**
2. 查询步骤卡 **紧凑/展开两态** + 操作收进「更多」
3. 列表 ↔ 画布 **双向联动高亮**
4. 左 rail 改 **抽屉式「新建查询」**，减少五层 chrome
5. 列表布局去 `padding-right: 354px` 硬编码

### P2 — 1–2 月（产品级打磨）

1. 画布 **缩放分级标签策略**（LOD）
2. Session 级 **undo/redo 可视化历史**
3. 高风险操作确认流（删步骤、改口径）
4. 响应式断点（1280 / 1440 / 1920 三档布局）
5. 空状态 / 加载 / 超大图（500+ 节点）性能提示

## 九、总结

这套原型已经具备 **「可演示、可开发对齐」** 的骨架，设计系统底座和组件拆分也到位。当前主要差距不在「有没有」，而在 **「主次是否分明、空间是否让给图谱、筛选语义是否一眼可懂」**。

若用一句话概括优化方向：

> **把 chrome 从五层收到三层，把筛选从底栏搬到顶栏，把 AI 从默认前台改为按需助手，把文案修到审计人员不会皱眉。**
