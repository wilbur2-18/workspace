**四、 核心需求与讨论点**
- **场景定制：** 大宗贸易的虚假贸易审计场景定制需求。（某个贸易的商品是否会形成”循环“）
- **关系挖掘：** 希望增加更多隐秘关系的识别与展示，提升穿透分析能力。
- **部署策略：** 探讨图谱形态做成“数据可用不可见”的模式并部署在专网上（即：仅显示实体间的关系路径，不提供底层原始数据查看权限），以降低合规压力并提升业务实用性。
- **展示优化：** 图谱信息量过载，需要做“减法”。通过对疑点进行分类并分级展示（重要疑点前置），提升视觉聚焦度。同时探讨通过视觉手段（如透明度）展示数据的时间属性。
- **场景化管理：** 场景管理需进行区分，分为“问题类场景”与“探索类场景”。
- **结果展现：** 探讨查询结果的“文本化”可能，利用大模型总结等技术手段。
- **分析深度：** 探索“图谱+数据分析”的结合，支持将 SQL 查询出的结果直接通过图谱展示。
- **隐形数据获取：** 关注 IT 类数据（如共享 WiFi）及基于特定规则推断的隐秘关系（如身份证前六位相同且同姓氏的“拟兄弟”关系）。
- **实体标签化：** 对国有企业等特定实体打标签，便于在分析时进行快速识别或数据剔除。
- **AI与开放性：** 关注图谱数据对 AI 的易读性，以及是否能提供查询接口供外部获取图谱数据。
- **安全合规：** 高度关注数据安全问题，在建设过程中严守安全底线。

**五、 存在的问题与挑战**
- **易用性：** 图谱易用性不够，操作门槛较高。目前业务人员高度依赖固聘人员进行操作，但固聘人员往往难以准确理解业务深层需求。
- **局限性：** 存在数据局限性，侧重于“查关系、查线索”，但在执行综合性分析（如企业整体分析）时能力不足。同时，新数据的拓展十分有限，目前受限于底层数据治理（如地方党政领导数据及上下级部门关系尚未入图）。
- **信息过载：** 图谱信息量太大，用户难以快速定位关键信息。
- **关系质量：** 部分关联关系不明确，存在无法溯源或关系描述不准确的问题，降低了核查的可信度。
- **功能侧重：** 查疑点能力偏弱（缺乏目的性时），而核查具体问题时效率较高。
- **访问限制：** 地方单位目前无法远程访问系统，查数据必须到厅里现场查看，使用极其不便。
- **部门协同：** 数据处与业务处室之间存在“两张皮”现象，技术与业务的深度融合尚存障碍，导致实战效能未完全释放。

**九、 领导总结与指示**

**【薛厅总结】**
1.  **全面覆盖与质量并重：** 在满足全覆盖要求的基础上完成图谱建设。不仅要追求“广度”，更要在“深度”和“精度”上狠下功夫，例如先在特定试点链路（链条）上打通并完善图谱。
2.  **强化培训与概念通俗化：** 在培训资料的编写上要更加用心，特别是针对特定专业名词的解释，应采用业务人员耳熟能详、便于理解的方式进行。
3.  **深耕重点应用场景：** 在保障业务处室基础支撑的同时，额外选定1-2个重点场景进行深度定制与打磨。目前平台在广度上表现尚可，但精度和深度亟待加强。
4.  **攻坚一线易用性与网络环境：** 必须解决一线人员“使用不方便”的痛点。除了优化具体的界面展现形式，还要重点研究并解决“数分网”与“专网”之间的数据访问及网络隔离问题。
5.  **探索前瞻性新场景：** 积极寻找新的应用场景（如银行流水穿透分析等），并针对试点方案广泛征集各方意见。

**【王厅总结】**
1.  **试点任务压舱：** 明确今年工作的首要压力是确保“审计署试点”任务的圆满完成。
2.  **场景闭环与实效：** 场景建设必须形成闭环，不能止于理论，要有明确的实效证明平台的价值。
3.  **破解“两张皮”现状：** 解决数据处与业务处室的技术业务融合难题。平台的核心目标是服务审计一线，必须以“实战”为需求和目标，衔接好以下三个关键环节：
    - **(1) 需求环节：** 建立定期收集项目需求的机制，坚持优先处理“边际效益高”的事情。
    - **(2) 试点环节：** 要求业务处室与开发人员密切合作，技术与业务深度绑定。
    - **(3) 用的环节：** 必须配齐使用说明并开展培训。此项要求不仅限于知识图谱，应涵盖所有在建的信息化项目。
4.  **守住安全底线：** 高度关注数据安全问题，在建设过程中必须严守安全底线。
