# 产品介绍 PPT 纯内容稿（产品交流优化版）

## 1. 人工智能 + 审计综合解决方案产品介绍

PPT展示：

- 数据治理平台
- 审计数据图谱平台
- 审计综合分析平台
- 产品能力交流

讲解要点：

本次交流重点不是介绍单点工具，而是说明三类平台如何协同支撑审计作业：先让数据可理解，再让关系可穿透，最后让任务可执行、成果可沉淀。

PPT展示：

讲解要点：

## 3. 整体产品思路

PPT展示：

价值重塑与效能跃升

- 从抽样核查到全量洞察
- 从单点核查到关系穿透
- 从人工操作到人机协同
- 从个人经验到组织能力

讲解要点：

这套方案的核心不是替代现有业务系统，而是在既有信息化基础上形成审计智能中枢，把数据、关系、任务和能力组织成可复核、可沉淀的审计作业闭环。

## 4. 产品矩阵：数据语义化、关系网络化、作业流程化

PPT展示：

| 产品 | 核心定位 | 主要产物 |
| --- | --- | --- |
| 数据治理平台 | 数据可理解 | 数据资产、重点实体、关系线索 |
| 审计数据图谱平台 | 关系可穿透 | 关系网络、穿透路径、图谱线索 |
| 审计综合分析平台 | 任务可执行 | 任务结果、证据定位、审计技能 |

一句话：数据语义化 -> 关系网络化 -> 作业流程化

讲解要点：

三类产品不是三套割裂系统，而是一条从数据资源到审计作业的能力链路。治理平台负责把原始数据变成可用资产，图谱平台负责把实体和关系组织起来，综合分析平台负责把资料、图谱、知识和技能编排为审计人员可复核的结果。

## 5. 审计人员的一次完整作业链路

PPT展示：

创建工作台 -> 加入资源 -> 发起分析 -> 执行任务 -> 复核结果 -> 沉淀能力

人机协同分工：

- 平台处理存量
- 审计人员定义变量
- 组织沉淀能力

讲解要点：

从审计人员视角看，平台最终表现为一个统一工作台。审计人员加入文件、库表、图谱和知识库后，可以通过提问或选择技能发起分析；系统负责任务拆解、资料读取、关系计算和证据定位；审计人员对疑点、摘录和关系链进行复核，并把确认后的方法沉淀为项目级或组织级技能。

PPT展示：

整体产品架构（页面从上到下展示）

| 架构层级 | 核心能力 | 主要承载 |

| 数据治理层 | 库表探查、字段语义识别、实体漫游、关系线索生成、加工 SQL 输出 | 数据治理平台 |
| 资源接入层 | 业务库表、文件资料、票据合同、工商资料、资金流水、制度依据 | 数据治理平台 / 审计综合分析平台 |

横向能力：

- 统一项目空间：按审计事项组织资料、库表、图谱、知识库、任务和结果

讲解要点：

这页建议按“多层架构图”呈现，而不是普通表格。视觉上最上方是能力沉淀层，承载模板、技能和应用；中间是审计作业层、图谱关系层和数据治理层，分别完成作业编排、关系网络化和数据语义化；最底部是资源接入层，承接审计数据和资料资源。两条横向能力贯穿全链路：一条是统一项目空间，解决资源组织问题；一条是全过程追溯，保证分析结果能够回到来源数据、关系路径和人工复核状态。

## 7. 数据治理平台

PPT展示：

数据治理平台

以数据探查、语义识别和数据漫游为核心，把原始数据转化为下游可使用的数据资产。

讲解要点：

这一部分重点不讲传统数据治理，而是讲审计场景下的数据价值发现：平台如何在庞杂库表中识别重要字段、发现重点实体、生成关系线索，并把这些结果交给图谱和综合分析平台继续使用。

## 8. 产品一：数据治理平台定位

PPT展示：

核心定位：

- 数据资源全量感知
- 字段语义自动识别
- 重点实体跨库发现
- 潜在关系线索生成
- 下游可用资产输出

讲解要点：

数据治理平台解决的是“数据能不能被理解、识别和调用”的问题。它不负责最终审计定性，也不承担图谱上的穿透推理，而是先发现哪些库表有价值、哪些字段代表关键实体、哪些主体之间可能存在关系，为后续入图和综合分析提供基础。

## 9. 数据语义感知：库表探查与字段语义理解

PPT展示：

能力链路：

全库表扫描 -> 表级摘要 -> 字段语义识别 -> 关键字段发现 -> 数据资产清单

关键字段：

身份证号、银行卡号、手机号、统一社会信用代码、车牌号

讲解要点：

平台会对目标数据库进行全量扫描，采集库、表、字段、类型、记录量等元数据，并结合字段结构、样例数据和上下文判断表的业务含义。字段层面会识别关键字段和审计分析价值，为后续实体搜集、关系挖掘和数据入图提供依据。

## 10. 实体漫游与关系线索生成：形成下游可用资产

PPT展示：

数据漫游：

- 跨库搜集重点实体
- 汇总实体分布位置
- 建立实体基础信息

关系线索：

- 多主体共现
- 跨表匹配
- 关系加工逻辑
- 加工 SQL

讲解要点：

数据漫游不是简单搜索，而是在多数据库、多系统、多表之间巡游重点实体，比如项目、企业、人员、账户等。平台会汇总实体出现在哪些表、出现频次、样例记录，并进一步生成待核实关系线索。这里生成的是线索，不是审计结论，需要结合来源记录和人工校验状态复核。

## 11. 对应案例：重点主体与关系线索准备

PPT展示：

案例：工程项目重点主体与关系线索准备

输入：项目、合同、供应商、发票、付款、人员、工商  
动作：探查字段、漫游实体、生成关系线索  
输出：重点主体清单、关系线索、可入图数据

讲解要点：

在工程项目审计中，平台先识别项目、合同、供应商、人员、资金账户等相关字段，再通过数据漫游搜集企业名称、统一社会信用代码、身份证号、手机号、银行卡号等重点实体。随后生成企业与项目、人员与企业、企业与账户之间的待核实关系，为图谱分析和综合分析平台继续使用。

## 12. 审计数据图谱平台

PPT展示：

审计数据图谱平台

通过本体建模、数据入图和关系计算，把审计对象组织为可查询、可穿透、可追溯的关系网络。

讲解要点：

这一部分重点讲关系能力。治理平台发现了数据和线索后，图谱平台负责把人员、企业、单位、项目、资金、票据、合同等对象组织成可以查询、穿透和推理的关系网络。

## 13. 产品二：审计数据图谱平台定位

PPT展示：

核心目标：

- 承接治理后的实体和关系
- 抽取非结构化文本关系
- 统一本体、实体、关系口径
- 完成实体关系入图
- 发现路径、链路和线索
- 沉淀模板化分析能力

讲解要点：

审计数据图谱平台面向关系穿透和线索发现。它既承接治理平台交付的结构化实体关系，也可以把非结构化文本抽取为可入图数据。通过本体约束和关系计算，平台可以发现路径、链路和待复核关系线索。

## 15. 非结构化资料的结构化抽取与入图准备

PPT展示：

适用资料：

- 工商变更
- 股权变更
- 董监高变更
- 法定代表人变更
- 招股书、公告、合同、制度

输出：实体清单、关系清单、时间线、可入图数据、来源定位

讲解要点：

很多审计关系并不天然存在于结构化表里，而是藏在工商变更、公告、合同和制度文本中。平台会抽取主体、时间、金额、事项和关系，标准化为实体清单、关系清单和历史变更时间线，并保留原始文本来源，方便后续复核。

## 16. 对应案例：企业股权穿透与关联方核查

PPT展示：

案例：企业股权穿透与关联方核查

输入：工商变更、股权结构、董监高、投资、合同、资金  
动作：结构化抽取、时间线整理、关系入图、股权穿透  
输出：关联方清单、穿透路径、交易核查线索、来源定位

讲解要点：

这个案例适合配真实图谱或股权穿透截图。口头上说明：平台先从工商和股权资料中抽取企业、人员、任职、投资、控制等关系，再围绕供应商、投资对象和重点人员开展穿透，最终输出疑似关联方、穿透路径和原始来源，供审计人员交叉验证。

## 17. 本体驱动的实体关系建模与数据入图

PPT展示：

本体建模：

人员、企业、单位、项目、资金、票据、合同

关系类型：

投资、任职、交易、付款、开票、关联、控制

入图产物：

图谱节点、图谱关系、关系属性、来源链接、任务记录

讲解要点：

本体是图谱平台的关系口径。通过本体先定义实体类型、关系类型、属性、索引和溯源链接，再把业务表字段映射成节点和边。这样后续查询、穿透和推理不会各用各的口径。

## 18. 关系计算与线索推理

PPT展示：

核心能力：

- 实体查询
- 路径计算
- 关系拓展
- 图上分析

输出：

关系链、穿透路径、异常结构线索、来源记录

讲解要点：

图谱分析围绕审计对象展开。审计人员可以从一个企业、人员、项目或资金账户进入关系网络，逐步查看上下游链路，也可以查询两个对象之间的最短路径、多跳路径和隐含关联。输出结果仍然是待复核线索，需要回到原始资料和凭证中核验。

## 19. 对应案例：工程项目供应链与票据资金一致性核查

PPT展示：

案例：工程项目供应链与票据资金一致性核查

输入：招投标、合同、采购、发票、付款、验收、供应商  
动作：构建关系网络、展开交易链路、一致性比对  
输出：供应链图谱、票据资金链路、待核实异常线索

讲解要点：

这个案例承接图谱平台的路径分析能力。平台把项目、合同、供应商、发票、货物和资金组织成关系网络，再将票据链路与合同单价、采购单价、验收记录、付款记录进行比对。最终输出疑似转包、围标、虚假采购、利益输送等线索材料。

## 20. 从图查询到模板化批量执行

PPT展示：

能力升级：

单次查询 -> 查询模板 -> 推理模板 -> 批量任务

典型场景：

批量导入供应商名单，执行关联方穿透，输出待复核线索表。

讲解要点：

图谱平台不只支持人工点选查询，还可以把高频查询逻辑沉淀成模板。审计人员批量导入供应商名单后，可以批量查询股权、任职、投资、控制和交易关系，并输出统一格式的结果表。

## 21. 审计综合分析平台

PPT展示：

审计综合分析平台

人机协同的统一工作入口

资料、库表、图谱、知识库、技能、任务、结果

讲解要点：

综合分析平台是审计人员实际使用的入口。它把前面治理出的数据资产、图谱关系、知识库和审计技能统一组织到工作台里，让审计人员可以围绕具体事项发起分析、查看任务、复核结果并沉淀方法。

## 22. 产品三：审计综合分析平台定位

PPT展示：

平台闭环：

资源管理 -> 上下文编排 -> 任务执行 -> 过程追溯 -> 结果复核 -> 能力沉淀

平台目标：

- 统一入口
- 统一编排
- 全程可追溯
- 结果可复核
- 方法可沉淀

讲解要点：

综合分析平台的重点是把审计作业变成可执行、可追溯、可复核的闭环。它调用治理后的数据资源，引用图谱关系和路径结果，并通过任务和技能把资料、库表、图谱和知识组织成可复核结果。

## 23. 多源上下文编排与任务执行

PPT展示：

三类能力：

统一项目工作空间  
沉浸式审计助手  
任务与结果管理

关键词：

资源引用、任务拆解、后台执行、结果树、历史版本、复核状态

讲解要点：

工作台按审计事项组织项目空间，统一管理文件、库表、图谱、知识库和已有结果。审计助手支持自然语言发起分析，也支持调用审计技能，并在对话中确认任务配置，把用户意图拆解为可执行步骤。任务完成后，结果进入统一结果树，支持预览、编辑、下载、版本查看和复核状态管理。

案例：会议纪要事项提取与证据定位

## 25. 审计技能体系与证据链闭环

PPT展示：

技能体系：

项目级技能 -> 组织技能 -> 技能市场

证据链闭环：

来源资料 -> 引用定位 -> 法规依据 -> 人工复核 -> 结果沉淀

讲解要点：

## 26. 对应案例：投资项目建设程序合规核查

PPT展示：

案例：投资项目建设程序合规核查

输入：立项、可研、初设、招投标、合同、付款、验收、制度

## 27. 技能市场：审计方法的组织级资产化与分发

PPT展示：

技能市场定位：

顶层技能知识与能力资产中心

核心能力：

- 分类标签
- 适用场景
- 版本状态
- 审核发布
- 权限范围
- 应用调用

讲解要点：

技能市场用于把项目中沉淀的成熟方法转化为可治理、可分发、可复用的组织级能力。项目级技能在工作台内运行，组织技能在多层级组织内维护和复用，技能市场作为顶层入口承载标准审计方法和专家沉淀能力。核心效果是上级沉淀方法，下级复用能力；总部统一标准，基层高效执行。

## 28. 应用中心：标准化审计能力的一键启动入口

PPT展示：

应用中心定位：

把成熟审计能力包装成可直接启动的业务应用

使用链路：

选择应用 -> 引用资源 -> 填写参数 -> 创建任务 -> 查看结果

讲解要点：

应用中心面向业务人员提供可浏览、可选择、可启动的 AI 审计应用目录。它把技能市场、组织技能、工作流和任务系统组合为业务入口，让用户不需要理解复杂技能配置，也能直接启动标准化审计能力。比如选择“投资项目资料完整性检查”应用后，用户只需要选择项目资料并填写少量参数，系统就会自动创建后台任务并输出检查结果。
