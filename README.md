# 产品工作区

这是一个个人产品工作区，用于沉淀日常产品工作、客户沟通、需求设计、原型、设计系统资产和历史参考资料。它不是单一产品目录，也不是单一代码仓库。

使用本工作区时，优先从当前目录结构和具体任务出发，不要假设固定文件名。目录角色比文件名更稳定。

## 目录角色

| 目录 | 作用 |
| --- | --- |
| `0 会议纪要` | 近期会议记录、需求调研、外部交流纪要。 |
| `x 工作日志` | 周报、阶段总结、个人工作记录。 |
| `1 综合分析平台` | 综合分析/审计分析相关产品资料、需求设计、高保真原型、历史备份。 |
| `2 数据图谱平台` | 数据图谱平台产品资料、需求池、需求设计、临时 Demo 和设计稿。 |
| `3 数据漫游` | 数据漫游相关产品资料。 |
| `3 智能体平台` | 智能体平台、智能问数等产品资料。 |
| `X 设计系统` | Pencil 文件、设计稿、组件/变量等设计系统资产。 |
| `x 留存文档` | 历史项目、通用参考、长期保留资料。 |
| `x 知识储备` | 工具、方法、技能和外部资料沉淀。 |

## 协作约定

- 先读目标目录附近的 `README.md` 或说明文件，再判断如何处理。
- 不为了整理而整理，不主动搬动业务资料。
- 需求设计以轻量需求卡和可执行说明为主。
- 原型目录以本地 `demo.html`、`ui/`、`assets/`、`scripts/` 和 README 为准。
- 历史备份、留存文档、工作日志和会议纪要默认不清理、不改名。
- 各产品线下与需求、原型、设计约束或正式产品文档无直接关系的临时事项，放入该产品的 `x 杂七杂八/<事项>/`，不要散放到需求设计目录根部。
- `x 杂七杂八` 采用事项文件夹管理；每次新事项单独建文件夹，必要时用简短 README 说明来源和用途。

## 其他关注

 `工作聚焦.md`为用户人工维护的工作台日志，不要修改里边的具体内容。该文件用于记录阶段性工作重心，不作为长期目录规则。
