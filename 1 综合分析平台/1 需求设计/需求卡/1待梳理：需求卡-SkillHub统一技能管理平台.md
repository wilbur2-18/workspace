# SkillHub 统一技能管理平台

**产品**：综合分析平台 / SkillHub  
**状态**：待梳理  
**更新**：2026-05-25  
**关联材料**：现有技能库、技能板块重构、生成技能任务、审计大数据平台 / 模型库建设思路

---

## 1. 原始需求 / 背景

技能库需要和平台部分解耦，延伸出一个类似 SkillHub 的平台，用于做上层的统一管理和维护。需要站在审计厅、审计署视角进行需求设计。

当前核心变化是技术路线从传统数据分析编程，转向 AI 驱动的技能、工具、工作流和智能应用，但业务本质没有变：审计机关仍然需要把可复用的分析方法、业务规则、模型和经验集中沉淀、统一治理、按需下发、持续迭代。

- 审计信息化长期围绕“集中分析、分散核查”“审计全覆盖”“模型库 / 方法库 / 数据平台”建设展开。
- 审计署和地方审计厅视角更关注统一规划、分级部署、跨地区复用、数据安全、执行留痕和成果可推广。
- 现有综合分析平台中的技能，更像项目级 / 工作台级可运行配置；SkillHub 应承载组织级能力资产治理。

## 3. 初步理解

SkillHub 不只是“更大的技能库”，而是审计 AI 能力资产中心。

它应该解决三类问题：

1. **统一治理**：审计署 / 审计厅可以统一维护公共技能、业务分类、适用范围、版本、权限和质量状态。
2. **分级复用**：地市、处室、项目组可以按业务场景引用、复制、定制技能，而不是各自重复配置。
3. **持续演进**：技能从个人经验、项目沉淀、生成技能任务中产生，经审核后进入组织资产，再被工作台、应用中心和任务系统调用。

---

## 4. 参考方案

### 方案 A：组织级技能资产库

以“技能”为核心对象，先把现有技能库平台化。

- 支持公共技能、厅级技能、地市技能、个人技能。
- 支持分类、标签、适用审计类型、适用资料类型、版本、审核状态。
- 支持技能发布、下架、复制、版本回退、使用统计。
- 工作台只引用 SkillHub 中的技能副本或受控版本。

适合先落地，改动相对可控。

### 方案 B：审计方法 / AI 能力 Hub

把技能、工具、提示词、工作流、模型配置、数据连接模板都作为能力资产管理。

- 技能是能力资产的一种。
- 工具 / MCP / API 连接作为可被技能和应用调用的底层能力。
- 工作流用于沉淀可运行的多步骤审计方法。
- 统一做权限、版本、依赖、测试、审核和上下线。

治理更完整，但范围大，适合作为中期目标。

### 方案 C：署厅级能力分发平台

面向审计署 / 审计厅做上级统一维护和下级分发。

- 上级维护标准技能、专项审计包、典型案例包。
- 下级可订阅、复制、适配本地数据口径。
- 支持分发范围、版本通知、更新说明、兼容性提示。
- 统计各地使用、反馈、问题和复用效果。

更符合审计机关纵向管理，但对组织权限和分发机制要求更高。

## 5. 初步范围

首版建议聚焦：

1. SkillHub 作为独立平台 / 模块入口，不继续只放在综合分析平台内部。
2. 技能对象统一登记：名称、分类、标签、适用场景、输入要求、输出形式、版本、来源、状态、维护人。
3. 技能生命周期：草稿、待审核、已发布、已下架、已废弃。
4. 技能来源：人工创建、工作台沉淀、生成技能任务、导入模板。
5. 技能使用：工作台引用、应用中心引用、任务创建引用。
6. 技能治理：权限、审核、版本、依赖、使用统计、问题反馈。

---

## 6. 影响面与风险

- 需要重新划分“平台技能库”和“工作台内引用技能”的边界。
- 技能板块重构中的分类、版本、权限和流转规则需要与 SkillHub 对齐。
- 生成技能任务、任务创建引用技能都需要和 SkillHub 对齐。
- 若一次性纳入工具、应用、模型、数据连接，范围会过大；首版需要先定核心对象。
- 审计机关场景必须考虑分级权限、内部共享、资产审计、敏感能力下发和版本一致性。

## 待确认问题

| 问题 | 影响 |
| --- | --- |
| SkillHub 首版是否只管理“技能”，还是同时纳入工具 / 工作流 / 应用模板 | 决定平台边界 |
| 技能是否需要署级、厅级、地市级、项目级多级来源 | 决定权限和分发模型 |
| 工作台引用技能时是引用固定版本，还是默认跟随最新发布版本 | 影响任务可复现和版本治理 |
| 生成技能任务产物是否默认进入个人草稿，再经审核进入 SkillHub | 影响资产入库流程 |
| 首批技能分类是否沿用审计业务分类、资料类型分类，还是按分析方法分类 | 影响信息架构 |
