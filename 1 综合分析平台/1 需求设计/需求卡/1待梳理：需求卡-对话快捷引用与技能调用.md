# 对话快捷引用与技能调用

**产品**：综合分析平台  
**状态**：待梳理  
**更新**：2026-05-29  
**关联材料**：审计助手对话输入框；资源区；结果区；技能区；当前 `@` / `/` 输入原型样式

---

## 1. 需求背景

当前原型中，对话输入框已具备输入 `@` 或 `/` 后弹出候选面板的基础样式，但能力口径还不完整。需要从头梳理：用户如何在输入问题时快捷指定引用文件、结果或其他资源，以及如何快捷选择本轮要使用的技能。

---

## 2. 目标场景

审计人员在输入问题时，可以不离开输入框，直接通过快捷符号选择本轮对话需要使用的上下文资源和技能：

- 输入 `@`，选择要引用的资料、结果或其他可引用资源。
- 输入 `/`，选择本轮要使用的技能。

选择完成后，输入框展示结构化引用标签或技能标签，发送消息时一并提交给大模型。

---

## 3. 本次做什么

### 3.1 触发规则

| 符号 | 用途 | 触发口径 |
| --- | --- | --- |
| `@` | 引用上下文资源 | 在输入框中输入 `@` 后展示可引用资源候选 |
| `/` | 使用技能 | 在输入框中输入 `/` 后展示可用技能候选 |

规则：

1. `@` 和 `/` 在行首或空格后触发。
2. 输入关键字后，候选列表按名称过滤。
3. `Esc` 关闭候选面板。
4. 点击候选项或键盘确认后完成选择。
5. 关闭面板后，普通文本输入不受影响。

### 3.2 `@` 引用资源

`@` 面板用于选择本轮对话的上下文资源。

建议候选范围：

| 类型 | 说明 |
| --- | --- |
| 文件 | 当前工作台中可引用的文件 |
| 文件夹 | 当前工作台中文件夹，可作为一组文件引用 |
| 结果 | 当前工作台中已有结果 |
| 数据库表 | 已加入工作台的库表 |
| 数据图谱 | 已加入工作台的数据图谱 |
| 知识库 | 已加入工作台的知识库 |

规则：

1. 候选项按类型分组展示。
2. 支持按名称搜索。
3. 已选择对象不重复添加。
4. 不可用对象不进入候选，或置灰并说明原因。
5. 未完成解析文件可被选择并正常作为结构化引用发送，输入区展示引用标签和文件状态。

### 3.3 `/` 使用技能

`/` 面板用于选择本轮对话要使用的技能。

规则：

1. 候选范围为当前工作台已引用或可使用的技能。
2. 支持按技能名称搜索。
3. 选择技能后，在输入框中展示技能标签。
4. 本轮对话只默认使用用户显式选择的技能。
5. 如果没有选择技能，大模型按普通对话处理。

### 3.4 选择后的输入框展示

选择完成后，输入框上方或输入区内展示结构化标签。

| 标签 | 展示内容 |
| --- | --- |
| 资源引用标签 | 类型、名称、移除入口 |
| 技能标签 | 技能名称、移除入口 |

规则：

1. 标签可移除。
2. 标签与用户输入文本一起构成本次消息上下文。
3. 发送后，消息气泡中展示本次引用数量、引用对象和使用技能。
4. 仅输入 `@文件名` 或 `/技能名` 文本但未选择候选时，不应当作结构化引用或技能调用。

---

## 4. 本次不做什么

1. 不做自然语言自动识别所有资源名称。
2. 不把 `/` 扩展为完整命令中心。
3. 不在本卡中定义技能配置确认弹窗。
4. 不改变资源区、结果区、技能区已有添加到对话逻辑。
5. 不做跨工作台资源搜索。

---

## 5. 验收口径

1. 用户在输入框输入 `@` 后，可以看到可引用资源候选面板。
2. 用户输入 `@` 后继续输入关键字，候选列表按资源名称过滤。
3. 用户选择资源后，输入框展示对应资源引用标签。
4. 用户在输入框输入 `/` 后，可以看到可用技能候选面板。
5. 用户输入 `/` 后继续输入关键字，候选列表按技能名称过滤。
6. 用户选择技能后，输入框展示对应技能标签。
7. 用户可以移除已选择的资源引用标签和技能标签。
8. 发送消息后，本次消息携带所选资源和技能；未选择候选的普通 `@` / `/` 文本不作为结构化引用。
9. 未完成解析文件被引用时，对话区展示引用标签和文件状态；需要读取内容时由大模型按需调用 OCR / 解析工具。

## 待确认问题

| 问题 | 影响 |
| --- | --- |
| `@` 首版是否覆盖文件夹、数据库表、图谱、知识库，还是先只覆盖文件和结果 | 影响候选面板复杂度 |
| `/` 首版只用于选择技能，还是也包含创建任务、保存结果等命令 | 影响是否会演变成命令中心 |
| 资源引用标签放在输入框上方，还是嵌入输入区内 | 影响后续 UI 设计 |
| 多个技能是否允许同时选择 | 影响大模型执行口径和技能冲突处理 |
