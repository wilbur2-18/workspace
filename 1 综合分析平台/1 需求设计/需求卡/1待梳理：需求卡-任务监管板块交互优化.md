# 任务监管板块交互优化

**产品**：综合分析平台  
**状态**：待梳理  
**更新**：2026-05-20  
**关联材料**：当前工作台右上角任务区；单次任务、跑批任务、生成技能任务；后续打包下载任务、打包上传任务

---

## 1. 需求背景

当前工作台中的任务展示主要集中在右上角一个较小区域，适合承载少量、轻量的执行状态提示。但随着平台能力扩展，任务类型已经不只是一类后台执行记录，而是逐步覆盖单次任务、跑批任务、生成技能任务，并会继续扩展到打包下载任务、打包上传任务等更多异步处理场景。

任务正在从“页面边角的状态提示”变成用户需要持续监管的重要功能对象。用户需要判断任务是否在排队、运行、失败、完成，必要时还需要进入任务详情、查看进度、处理中止或重跑、追踪产物和异常原因。现有右栏小区域承载能力有限，后续如果继续叠加任务类型和操作，容易出现信息拥挤、状态不可见、监管路径分散的问题。

本需求先记录任务模块升级的背景和问题，不在本卡中直接确定最终交互方案。

---

## 2. 目标场景

用户在综合分析平台中发起分析、跑批、技能生成、打包下载或打包上传等异步任务后，可以在一个更适合监管的任务区域中持续查看任务状态、处理异常任务，并追踪任务结果或产物，而不是只依赖右上角小区域的简单状态展示。

---

## 3. 待梳理范围

### 3.1 任务对象扩展

后续需要统一梳理不同任务类型在平台中的展示和监管方式。

| 任务类型 | 当前 / 预期状态 | 需要关注的问题 |
| --- | --- | --- |
| 单次任务 | 已存在 | 如何查看执行状态、进度、失败原因和结果入口 |
| 跑批任务 | 已存在 | 如何查看父任务、子任务、排队、失败重跑和整体进度 |
| 生成技能任务 | 已存在 | 如何跟踪生成过程、生成结果和失败处理 |
| 打包下载任务 | 后续可能新增 | 如何展示打包进度、下载入口、过期或失败状态 |
| 打包上传任务 | 后续可能新增 | 如何展示上传进度、解析 / 入库进度、失败原因和重试入口 |

### 3.2 任务区域定位

现有右上角小任务区需要重新评估是否仍适合作为主要任务入口。

待梳理问题：

1. 任务是否需要成为独立一级功能板块，还是保留在工作台内但扩大承载区域。
2. 任务入口是否需要支持全局查看，还是只查看当前工作台 / 当前项目内任务。
3. 任务列表、任务详情、任务操作和任务产物之间应如何组织。
4. 原右上角任务区后续是保留为快捷入口、摘要提醒，还是被新的任务板块替代。

### 3.3 任务监管能力

后续方案需要重点覆盖用户监管任务的基本能力。

| 能力 | 待梳理内容 |
| --- | --- |
| 状态查看 | 排队中、运行中、成功、失败、中止等状态如何展示 |
| 进度查看 | 不同任务类型是否都有进度，进度口径是否一致 |
| 异常处理 | 失败、中止、超时、部分成功等状态如何处理 |
| 操作入口 | 中止、重跑、删除、下载、查看结果等操作放在哪里 |
| 结果追踪 | 任务完成后如何回到分析结果、技能、文件包或上传产物 |
| 通知提醒 | 任务完成或失败后是否需要提醒，提醒出现在哪里 |

---

## 4. 本次不做什么

1. 本卡不直接确定任务板块的最终布局和交互方案。
2. 不调整现有单次任务、跑批任务、生成技能任务的执行逻辑。
3. 不定义打包下载、打包上传任务的完整业务规则。
4. 不处理任务调度、并发、优先级等后端策略。
5. 不替代已有排队提醒、任务排队态等单点需求卡。

---

## 5. 后续验收方向

后续正式梳理时，至少需要能验证以下方向：

1. 用户可以在明确入口中查看当前相关任务，而不是只能依赖右上角小区域。
2. 不同任务类型可以被统一识别、筛选或查看，任务状态口径清晰。
3. 用户可以从任务进入详情，并看到任务进度、异常原因和相关产物入口。
4. 任务完成、失败、中止等关键状态不会被隐藏在页面边角，用户能够及时发现并处理。
5. 原右上角任务区与新任务板块的关系明确，不出现两个入口信息不一致的问题。

---

## 待确认问题

| 问题 | 影响 | 建议处理 |
| --- | --- | --- |
| 任务板块是全局能力还是工作台内能力 | 影响入口层级、数据范围和权限边界 | 后续结合工作台、项目列表和任务详情页统一判断 |
| 右上角任务区后续是否保留 | 影响现有页面布局和用户习惯迁移 | 可以先定位为任务摘要 / 快捷入口，再评估是否替换 |
| 打包下载、打包上传任务是否纳入同一任务模型 | 影响任务类型、状态和操作抽象 | 在正式方案中对比现有任务对象后再确定 |
| 是否需要任务通知机制 | 影响全局提醒、消息中心或页面内提示设计 | 与任务监管入口一起梳理，避免只做列表不做提醒 |
