# 对话中歧义选择

**产品**：综合分析平台  
**状态**：待梳理  
**更新**：2026-05-23  
**关联材料**：对话助手；资源树；结果树；任务配置；工具执行

---

## 1. 需求背景

用户在对话中经常会用自然语言表达目标，例如“删除这个”“用上次的报告”“把那个文件加进来”。这类表达对人来说可能依赖上下文，但对助手来说可能存在多个候选对象或多个可选参数。

歧义选择的核心不是风险决策，而是先让用户选对对象或参数。它应与删除、覆盖等风险决策区分开，避免用户以为“选中对象”就等于已经同意执行危险操作。

---

## 2. 目标场景

当助手无法唯一确定用户要操作的对象、范围或参数时，在对话中展示候选选择卡。用户选择后，助手再继续后续流程：如果后续是高风险操作，进入操作确认；如果后续是任务创建，进入任务配置确认。

---

## 3. 本次做什么

### 3.1 触发范围

| 类型 | 触发规则 | 示例 |
| --- | --- | --- |
| 对象不唯一 | 存在多个同名、相似名称或上下文相关对象 | 多个“付款异常报告” |
| 范围不明确 | 用户没有明确使用哪个文件夹、资源范围或结果范围 | “用上次那些资料” |
| 参数不明确 | 任务配置、输出位置、OCR 范围等存在多个合理选项 | “按之前的配置跑一遍” |
| 指代不清 | “这个”“那个”“上次的”无法唯一映射 | “删除这个结果” |

### 3.2 选择卡内容

| 内容 | 规则 |
| --- | --- |
| 标题 | 用选择语气表达，例如“请选择要操作的结果” |
| 候选项 | 展示候选对象名称、类型、路径、更新时间或来源任务 |
| 选择方式 | 单选为主；需要多选时明确展示多选状态 |
| 辅助信息 | 展示能帮助区分的字段，例如所属文件夹、生成时间、任务来源 |
| 操作按钮 | “确认选择”“取消” |
| 风险样式 | 默认不使用危险色，避免与删除确认混淆 |

### 3.3 后续流转

| 选择后动作 | 规则 |
| --- | --- |
| 后续为只读操作 | 选择后可直接执行，例如打开、查看、引用 |
| 后续为风险操作 | 选择后进入“结果树敏感变更决策” |
| 后续为任务创建 | 选择后进入“对话中任务配置确认” |
| 仍存在歧义 | 继续展示下一层选择，不直接执行 |

说明：

- 歧义选择只解决“选哪个”，不承担删除、覆盖、中止等风险决策。
- 如果候选项过多，应先展示最相关候选，并支持搜索或收起展开，具体交互待设计。

---

## 4. 本次不做什么

1. 不做模型自动猜测并直接执行高风险操作。
2. 不把歧义选择卡做成危险决策卡。
3. 不处理完整搜索中心或高级筛选能力。
4. 不做跨会话长期记忆中的对象指代推断。
5. 不替代任务配置确认和操作确认。

---

## 5. 验收口径

1. 当用户指令中的对象或参数不唯一时，系统展示歧义选择卡，而不是直接执行工具。
2. 候选项至少展示名称、类型和路径 / 来源等区分信息。
3. 用户确认选择后，助手按所选对象继续后续流程。
4. 如果后续动作是删除、覆盖、中止等风险操作，选择后还需要展示操作确认。
5. 如果后续动作是创建任务，选择后进入任务配置确认。
6. 用户取消选择后，工具不执行，并在对话中反馈已取消。
7. 歧义选择卡不使用危险决策样式，避免与风险决策混淆。
