# 大模型操作审批（结果树相关）

**产品**：综合分析平台  
**状态**：已上线  
**更新**：2026-06-01  
**关联材料**：对话助手；工具执行；结果树

---

## 1. 需求背景

助手后续会具备部分结果树操作能力。如果所有工具动作都要求用户决策，会频繁打断对话；但删除、覆盖、移动目录这类动作会破坏既有结果资产或结构，需要用户明确同意后再执行。

本需求只处理结果树相关操作的审批交互与界面样式，不定义审批流，也不定义哪些动作必须进入审批。

新增反馈：用户认为删除审批不一定有必要，更倾向于大模型不要直接删除结果。大模型应优先通过新建结果、新建版本或新建副本完成操作；如果确实需要支持删除结果，需要先考虑回收站 / 软删除能力，保证误删后可以恢复。

---

## 2. 目标场景

当后端返回一条需要用户确认的结果树操作时，前端在对话区展示审批信息。用户允许后继续执行；拒绝或 60 秒未操作则不执行。

---

## 3. 本次做什么

### 3.0 待重新评估的产品方向

| 方向 | 说明 |
| --- | --- |
| 大模型默认不删除结果 | 大模型不直接执行删除结果；如需清理，由用户在结果树中手动操作 |
| 优先新建而非覆盖 / 删除 | 大模型生成内容时优先新建结果、版本或副本，避免破坏既有产物 |
| 删除前置回收站能力 | 如果后续允许删除结果，建议先支持回收站 / 软删除，可恢复后再评估是否仍需要审批 |
| 审批范围收缩 | 审批不再默认围绕“删除结果”展开，只保留给确实不可逆或高风险的操作 |

说明：以上是新增需求反馈，后续设计时需要重新判断本卡是否继续以“删除审批”为主，还是改为“限制大模型破坏性操作 + 可恢复删除”。

### 3.1 前后端边界

- 后端负责返回：是否需要审批、审批状态、工具名称、动作名称、对象信息、剩余时间、历史审批记录、技术细节字段与代码块。
- 前端负责定义：审批信息在对话中的展示结构、状态切换、按钮行为、超时反馈、历史记录回放方式、技术细节区样式。
- 本需求不定义：审批判定逻辑、对象分类规则、权限体系、审批流转规则。
- 对象不明确时，仍先进入“对话中歧义选择”；任务配置提交仍进入“对话中任务配置确认”。
- 本期只覆盖结果树相关审批展示，资源、任务、数据库表等对象另行定义。

### 3.2 决策卡内容

| 内容 | 规则 |
| --- | --- |
| 头部 | 统一显示“工具调用请求”；右侧显示剩余时间或审批结果 |
| 问题句 | 按“是否允许调用「工具名」执行某动作”生成，问题句中包含对象名称 |
| 影响摘要 | 主卡下方展示“影响：图标 + 对象名称”；批量时展示数量和前几项 |
| 技术细节 | 展示工具、动作、对象、路径、审批编号、状态、原始参数等；字段与代码块支持滚动 |
| 按钮 | 统一使用“允许 / 拒绝” |
| 超时 | 60 秒未操作，默认取消 |

### 3.3 对话展示

| 状态 | 对话展示 |
| --- | --- |
| 历史审批 | 以工具行形式展示已超时、已拒绝、待确认等历史记录；已完成项可展开查看审批详情 |
| 待审批 | 底部展示当前可操作审批卡，按钮可点击，显示剩余有效时间 |
| 已允许 | 历史记录更新为“已允许，已执行……”；当前审批卡不再可操作 |
| 已拒绝 | 历史记录更新为“已拒绝，未执行……”；当前审批卡不再可操作 |
| 已超时 | 历史记录更新为“已超时，未执行……”；当前审批卡不再可操作 |

说明：本卡只定义审批信息在对话中的展示逻辑与界面状态；同意或拒绝后的模型回复策略不在本需求内定义。

---

## 4. 本次不做什么

1. 不做多人审批、权限体系或永久放行。
2. 不承载任务配置确认和歧义选择。
3. 不要求编辑结果正文、新增结果时打断用户决策。
4. 不覆盖资源、任务、数据库表等对象。
5. 不在本卡中完整定义回收站能力；如确认要做回收站，应另行拆分结果回收站需求。

---

## 5. 验收口径

1. 当后端返回待审批项时，界面展示当前审批卡，包含头部、问题句、影响摘要、按钮和剩余时间。
2. 当后端返回历史审批记录时，界面先展示历史工具行；已完成项可展开查看审批详情。
3. 当前审批卡与历史审批记录使用同一套审批语义，但当前审批卡保留操作按钮，历史记录为只读。
4. 批量对象场景下，主卡与详情区都能展示数量、对象类型和影响范围。
5. 技术细节区支持字段信息与代码块混排，并在超出最大高度时内部滚动。
6. 用户允许、拒绝、超时后，界面分别更新为对应结果态，且不再提供重复操作入口。
7. 审批相关界面样式在对话区内保持一致：待审批卡用于当前决策，历史审批项用于回放和查看详情。
