# 已完成任务支持重跑

**产品**：综合分析平台  
**状态**：已上线  
**更新**：2026-06-01  
**关联材料**：任务列表；任务详情；单次任务；跑批任务；生成技能任务；打包下载任务

---

## 1. 需求背景

当前任务区已支持对失败、排队中或运行中的部分任务进行重跑、中止、删除等操作，但已完成任务通常只提供查看结果、下载或删除。

实际使用中，即使资源和任务输入不变，大模型生成结果也可能存在差异；同时用户可能已经调整了技能配置，希望基于当前技能配置重新生成一版结果。因此已完成任务需要支持重跑。

---

## 2. 目标场景

用户在任务列表或任务详情中查看已完成任务时，可以通过“重跑 / 重新打包”再次执行该任务。系统在执行前让用户确认是否删除上次执行产出的结果，然后按任务类型进入新的执行流程。

---

## 3. 本次做什么

### 3.1 操作入口

| 位置 | 规则 |
| --- | --- |
| 任务列表 / 任务树 | 已完成单次任务、生成技能任务在“更多”中展示“重跑” |
| 任务详情 | 已完成任务在详情页顶栏“更多”中展示“重跑” |
| 打包下载任务 | 已完成打包下载任务展示“重新打包” |
| 跑批父任务 | 跑批父任务提供“一键重跑” |
| 跑批子任务 | 已完成和失败子任务提供“重跑” |

### 3.2 重跑规则

| 对象 | 规则 |
| --- | --- |
| 单次任务 | 基于原任务名称、资源范围、任务指令和当前可用技能配置创建新的任务记录 |
| 生成技能任务 | 基于原生成要求和引用上下文创建新的生成任务记录 |
| 打包下载任务 | 基于原打包范围和下载格式创建新的打包下载任务记录 |
| 跑批父任务 | 在当前跑批任务内重新执行全部子任务，父任务进度随子任务状态更新 |
| 跑批子任务 | 仅重跑当前子任务，不影响其他子任务 |

补充规则：

1. 单次任务、生成技能任务和打包下载任务重跑后生成新的任务记录，原任务记录保留。
2. 跑批父任务和跑批子任务在当前跑批结构内重新流转，不新增跑批父任务或子任务记录。
3. 新任务或重跑中的子任务先进入排队中，再按既有任务状态流转为运行中、已完成或失败。
4. 普通重跑任务名称默认沿用原任务名称并追加“重跑”；打包下载任务追加“重新打包”。
5. 若原任务引用的资源、结果、技能或配置已不存在，系统不直接重跑，并提示原因。

### 3.3 确认规则

用户点击“重跑 / 重新打包 / 一键重跑”后，先展示轻量确认弹窗。

| 内容 | 规则 |
| --- | --- |
| 标题 | 按操作展示“确认重跑任务 / 确认重跑子任务 / 确认重新打包”等 |
| 提示文案 | “请确认是否删除上次执行产出的结果” |
| 产物处理 | 提供“保留当前结果 / 删除当前结果”两个选项，默认保留 |
| 操作按钮 | “取消 / 确认重跑” |

选择“删除当前结果”时，重跑前同步删除上次执行产出的结果、技能产物或文件包；选择“保留当前结果”时，新产出与原产出并存。

---

## 4. 本次不做什么

1. 不支持在重跑前编辑完整任务配置。
2. 不支持重跑前修改任务名称。
3. 不处理任务调度优先级、并发策略或插队。
4. 不做跑批父任务下的部分子任务选择；第一版只支持整批重跑和单个子任务重跑。
5. 不改变失败任务、排队中任务、运行中任务已有的中止 / 重跑规则。

---

## 5. 验收口径

1. 已完成单次任务、生成技能任务在任务列表和任务详情中可以看到“重跑”入口。
2. 已完成打包下载任务可以看到“重新打包”入口，并创建新的打包下载任务记录。
3. 跑批父任务可以发起“一键重跑”，所有子任务重新进入执行流程。
4. 已完成和失败跑批子任务可以单独重跑，且不影响其他子任务。
5. 重跑确认弹窗展示“请确认是否删除上次执行产出的结果”，并提供“保留当前结果 / 删除当前结果”。
6. 用户确认后，新任务或子任务按既有状态进入排队中、运行中、已完成或失败。
7. 普通任务和打包下载任务重跑后生成的新任务名称能与原任务区分。
8. 原任务引用资源或配置失效时，系统不直接重跑，并提示原因。
