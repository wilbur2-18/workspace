# 排队提醒与任务排队态

**产品**：综合分析平台  
**状态**：已上线  
**更新**：2026-06-01  
**关联材料**：审计助手对话页、任务区、跑批子任务列表；对话排队单点说明已并入本文

---

## 1. 需求背景

工作台中存在两类容易被用户误解的“等待”：一类是审计助手提交问题后，模型请求因繁忙进入排队，用户容易误以为问题没有发送成功或页面卡住；另一类是跑批父任务下存在多个子任务排队执行，用户只能看到“排队中”状态，但难以判断子任务的先后顺序。

同时，任务区页头同时露出“刷新”和“中止”等操作时，中止这类破坏性操作过于靠前，误触成本高。本次优化重点是让“等待中但仍在推进”的状态更可见，并把任务区高频刷新与高风险操作分开，不改变模型调度、跑批调度和资料解析队列规则。

---

## 2. 目标场景

审计人员在工作台中使用审计助手或查看跑批任务时，可以清楚判断当前请求或子任务是否已经进入排队、排在什么位置，以及哪些操作会刷新列表、哪些操作会中止或重跑任务；在等待期间，不需要通过重复发送、刷新页面或逐条点开子任务来确认系统是否仍在处理。

---

## 3. 本次做什么

### 3.1 排队语义边界

本需求只处理“模型对话排队”和“跑批子任务排队”两类状态，避免与资料解析队列混用。

| 对象 | 本次是否覆盖 | 用户看到的反馈 | 说明 |
| --- | --- | --- | --- |
| 模型对话请求 | 是 | 输入区上方“排队提醒” | 表示本次提问已提交，但模型尚未开始正常生成 |
| 跑批子任务 | 是 | 子任务行“第 N 位” | 表示同一父任务下该子任务的排队顺序 |
| 资料排队 / 解析中 | 否 | 维持现有状态筛选与操作规则 | 不新增解析排队位次，不改资料状态筛选条 |

说明：

- 对话排队提醒不得用于表示资料是否在解析，也不得用于表示跑批子任务是否在执行。
- 跑批子任务位次只服务于父任务下钻后的子任务列表，不扩展到任务列表、结果列表或资料列表。

### 3.2 审计助手对话排队提醒

当当前会话存在一条已提交但尚未进入正常生成的模型请求时，在对话输入框上方展示排队提醒。

| 要素 | 规则 |
| --- | --- |
| 展示位置 | 贴近输入区上沿，宽度与输入区对齐并水平居中，不进入对话消息流 |
| 标题 | 固定展示“排队提醒”，配预警色信息图标 |
| 正文 | “当前模型请求量较高，你目前排在第 N 位。请耐心等待” |
| 排位 N | 展示当前请求的排队位次，最小为 1，不展示 0、负数、空值或 NaN |
| 伴随内容 | 保留用户本次提问，以及已展示的思考 / 工具调用步骤 |
| 操作 | 不提供取消、插队、重试等按钮 |

提醒消失规则：

- 请求开始正常生成或执行时，隐藏排队提醒。
- 用户暂停生成、在同会话发送新消息、切换到其他历史会话时，清理当前提醒。
- 切回仍处于排队状态的会话时，可恢复对应提醒和排位。

### 3.3 历史会话菜单

历史会话下拉用于切换真实会话，不承担演示场景分组说明。

| 项 | 规则 |
| --- | --- |
| 菜单结构 | 扁平列表，一项对应一个会话 |
| 会话名称 | 仅展示真实会话标题，不出现“案例”“演示场景”等分组或占位文案 |
| 切换排队态 | 切到无排队会话时不展示提醒；切回排队会话时恢复提醒与排位 |

### 3.4 任务区刷新与高风险操作收纳

任务区页头保留“刷新”作为外侧高频操作，将中止、重跑、删除等操作收纳到“更多”中，降低误触。

| 区域 | 外侧操作 | 更多菜单 | 规则 |
| --- | --- | --- | --- |
| 跑批子任务列表页头 | 刷新 | 中止父任务、全部重跑、仅失败重跑、删除 | 刷新仅重新加载任务列表，不刷新中间助手对话 |
| 任务详情顶栏 | 刷新 | 中止、重跑、删除 | 仅可操作任务展示相关菜单项 |
| 子任务行 | 不单独放中止图标 | 更多 / 右键菜单 | 行尾不重复暴露破坏性操作 |

说明：

- 刷新按钮提示需明确“重新加载任务列表，不刷新对话”。
- 中止、删除等破坏性操作进入“更多”后，仍按既有二次确认或状态规则执行；本需求不重新定义任务操作后状态。

### 3.5 跑批子任务排队位次

在跑批父任务下钻后的子任务列表中，仅对“排队中”子任务展示排队位次。

| 要素 | 规则 |
| --- | --- |
| 展示文案 | “第 N 位” |
| 位次口径 | 同一父任务下，按当前子任务列表顺序，对“排队中”子任务从 1 开始编号 |
| 展示样式 | 小胶囊标签，数字 N 使用预警色并加粗 |
| 左侧图标 | 排队中时钟图标使用预警色，仅作用于子任务列表 |
| 悬停行为 | 默认显示位次；悬停该行时隐藏位次并露出“更多”；移开后恢复 |
| 非排队状态 | 运行中、成功、失败子任务不展示“第 N 位” |

说明：

- 若后端提供调度器真实位次，以接口位次为准；若暂未提供，则按父任务内列表顺序生成展示位次。
- 位次只表达当前列表中的排队顺序，不承诺全局等待时间或预计完成时间。

## 4. 本次不做什么

1. 不做资料文件在“排队中 / 解析中”状态下的排队位次展示或专项排队 UI。
2. 不调整模型、跑批任务、资料解析的调度策略、优先级和并发配置。
3. 不新增取消排队、插队、优先执行、预计等待时长等能力。
4. 不把模型排队提醒写入对话历史、分析结果、技能沉淀或导出内容。
5. 不改变跑批下钻、子任务状态筛选、分页、父任务进度等既有结构。
6. 不在本需求内重新定义排队期间是否允许继续发问，沿用当前发送规则。

---

## 5. 验收口径

### 5.1 对话排队提醒

1. 模型请求进入排队状态时，审计助手输入框上方展示“排队提醒”。
2. 提醒正文显示“当前模型请求量较高，你目前排在第 N 位。请耐心等待”，且 N 不小于 1。
3. 排队期间，对话区仍保留用户本次提问和已展示的思考 / 工具调用步骤，提醒不进入历史消息流。
4. 请求开始生成、用户暂停生成、同会话新发消息或切换到非排队会话后，提醒消失。
5. 历史会话下拉为扁平会话名列表，不出现“案例 / 演示场景”等分组文案。
6. 提醒不遮挡发送按钮、@ 引用入口、技能入口和输入区上方的引用 / 技能选择面板。

### 5.2 任务区操作收纳

1. 跑批子任务列表页头展示“刷新 + 更多”，不再单独展示中止图标。
2. 任务详情顶栏展示“刷新 + 更多”，中止、重跑、删除等操作在“更多”内触达。
3. 点击任务区刷新后，任务列表重新加载，中间助手对话和输入内容不被清空。
4. 子任务行尾不重复展示独立中止图标，相关操作通过“更多”或右键菜单触达。

### 5.3 子任务排队位次

1. 跑批子任务列表中，“排队中”子任务左侧时钟图标使用预警色。
2. “排队中”子任务右侧展示“第 N 位”胶囊，N 按同一父任务下排队子任务的列表顺序递增。
3. 运行中、成功、失败子任务不展示“第 N 位”。
4. 悬停排队子任务行时，“第 N 位”隐藏并露出“更多”；移开后恢复位次展示。
5. 资料“排队中 / 解析中”视图不出现“第 N 位”或类似解析排队位次。

## 关键决策

| 决策点 | 结论 | 原因 |
| --- | --- | --- |
| 本期范围 | 只覆盖对话排队和跑批子任务排队 | 资料解析排队展示另行处理，降低联调和验收范围 |
| 对话与任务排队 UI | 语义分开，不共用同一提醒 | 对话等待和任务排队的对象、位置、用户动作不同 |
| 子任务位次文案 | 使用“第 N 位”胶囊 | 适合侧栏窄空间，能直接表达顺序 |
| 任务页头主操作 | 外侧保留刷新，高风险操作进更多 | 刷新高频且低风险，中止 / 删除需要降低误触 |

## 待确认问题

| 问题 | 影响 | 建议处理 |
| --- | --- | --- |
| 模型排队位次是否由后端实时返回 | 影响对话提醒中 N 的数据来源 | 联调前可用 demo 默认值；正式验收需绑定接口字段 |
| 子任务“第 N 位”是否使用调度器全局顺序 | 影响位次计算口径 | 若接口提供全局位次则使用接口；否则按父任务内排队子任务顺序展示 |
| 资料解析排队 UI 是否单独立项 | 影响后续需求拆分 | 将资料解析位次、资料状态筛选条工具栏等另开需求卡 |
