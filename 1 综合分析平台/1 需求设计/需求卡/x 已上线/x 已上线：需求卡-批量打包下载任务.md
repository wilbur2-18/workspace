# 批量打包下载任务

**产品**：综合分析平台  
**状态**：已上线  
**更新**：2026-07-02  
**关联材料**：结果树打包下载；资源、结果与任务批量操作；任务监管板块

---

## 1. 需求背景

当前结果文件和结果文件夹支持下载 / 打包下载。后续批量下载会涉及多个结果文件、文件夹，以及文件中的 Markdown 转 PDF 后再打包的场景，处理时间可能明显长于普通下载。

本次需求将“批量打包下载”从即时操作调整为异步任务：用户发起后无需停留等待，可在任务区查看进度，并在完成后下载产物。

---

## 2. 目标场景

用户在结果区选择多个结果文件或结果文件夹后，先通过文件打包任务弹窗确认打包方式，再创建后台打包任务。任务执行过程通过任务列表监控，完成后用户从任务中下载文件包。

---

## 3. 本次做什么

### 3.1 触发入口

| 入口 | 规则 |
| --- | --- |
| 结果批量操作条 | 选中结果文件 / 文件夹后，点击下载或打包下载，打开文件打包任务弹窗 |
| 结果文件夹行级菜单 | 沿用结果文件夹“打包下载”入口，打开文件打包任务弹窗 |

### 3.2 文件打包任务弹窗

用户点击打包下载后，先进入文件打包任务弹窗，确认如何打包，再创建任务。

| 配置项 | 规则 |
| --- | --- |
| 任务名称 | 必填，默认按“结果打包下载-时间”生成，用户可修改 |
| 打包范围 | 展示已选数量、结果文件数量、文件夹数量 |
| 目录结构 | 支持保留层级 / 剔除层级 |
| 下载格式 | 单选：全部保留原始格式，或全部按 MD 转 PDF |
| 转换提示 | 选择 MD 转 PDF 时提示需要转换处理，耗时更长 |

弹窗操作：

- 点击“创建任务”后关闭弹窗，并提示“已创建打包任务，可在任务列表查看进度”。
- 点击“取消”不创建任务，返回原结果区选择状态。
- 任务名称为空时不能创建任务，并在任务名称输入框下方提示。
- 弹窗只处理打包配置，不展示完整文件预览和单文件剔除。

### 3.3 任务状态与操作

| 状态 | 展示口径 | 可操作 |
| --- | --- | --- |
| 排队中 | 等待开始打包 | 中止 |
| 运行中 | 正在转换和生成压缩包 | 中止 |
| 已完成 | 文件包已生成 | 下载 |
| 失败 | 未生成可用文件包 | 查看原因、重新打包 |

说明：

- 打包任务状态与其他任务保持统一，不新增“部分完成”状态。
- 如果部分文件打包或转换失败，由后端按任务结果判定为“已完成”或“失败”；当前原型在任务详情中展示失败原因，失败文件明细以后端返回为准。

### 3.4 产物规则

- 打包产物为 ZIP。
- 原始格式输出沿用当前结果文件格式。
- MD 转 PDF 输出表示将本次打包范围内的 Markdown 内容统一转为 PDF 后下载。
- 首版不支持同一次打包中部分文件转 PDF、部分文件保留原始格式。
- 文件夹打包继续支持保留层级 / 剔除层级。
- 任务完成后在任务列表 / 任务详情提供下载入口。
- 下载包有效期暂定 30 天；过期后保留任务记录，但需要重新打包。

### 3.5 任务列表与详情

- 任务列表中展示用户填写的任务名称，任务类型展示为“打包下载”。
- 任务详情展示打包范围、下载格式、任务状态、失败原因和下载入口。

---

## 4. 本次不做什么

1. 不做 PDF 模板、水印、页眉页脚配置。
2. 不做下载包内容预览和手动剔除单个文件。
3. 不做任务优先级和调度策略配置。
4. 不做站内消息中心或浏览器通知。
5. 不改变现有资源、结果、任务的多选边界。
6. 不做部分文件转 PDF、部分文件保留原始格式，也不做 Word 等其它导出格式。

---

## 5. 验收口径

1. 用户在结果区选择可下载结果后，点击下载 / 打包下载会打开文件打包任务弹窗。
2. 用户选择 MD 转 PDF 时，系统明确提示转换处理会增加等待时间。
3. 用户在弹窗中填写任务名称并点击“创建任务”后，弹窗关闭，并在任务列表看到对应名称的“打包下载”任务。
4. 打包任务状态与其他任务保持统一，至少能区分排队中、运行中、已完成、失败。
5. 任务完成后，用户可以从任务列表或任务详情下载 ZIP 文件。
6. 任务失败时，用户可以查看失败原因并重新打包。
7. 存在单个文件打包或转换失败时，不新增“部分完成”任务状态；任务详情展示失败原因，失败文件明细以后端返回为准。
