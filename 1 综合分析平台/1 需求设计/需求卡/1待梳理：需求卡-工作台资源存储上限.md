# 工作台资源存储上限

**产品**：综合分析平台  
**状态**：待梳理  
**更新**：2026-05-22  
**关联材料**：工作台资源；资料上传；资源文件树；上传与解析中文件可用性优化

---

## 1. 需求背景

当前资料上传已有单文件大小限制，但工作台维度缺少资源存储总量上限。随着用户持续上传普通文件、ZIP 压缩包和后续可能的打包上传任务，单个工作台可能沉淀大量资源，影响存储成本、解析性能和后续任务稳定性。

本次需求先记录：工作台资源需要有存储上限，并在用户上传和管理资源时给出清晰反馈。

---

## 2. 目标场景

用户在工作台上传或管理资源时，可以知道当前工作台资源已使用多少存储、剩余多少容量；当上传会超过上限时，系统应提前提示并阻止继续上传，避免上传后才失败。

---

## 3. 本次做什么

### 3.1 存储上限口径

| 对象 | 规则 |
| --- | --- |
| 统计范围 | 当前工作台下的资源文件 |
| 统计内容 | 普通上传文件、ZIP 解压后的文件、后续打包上传形成的资源文件 |
| 文件夹 | 文件夹本身不计容量，仅统计其下文件 |
| 已删除资源 | 不计入当前已用容量 |
| 解析结果 / 分析结果 | 不纳入本卡的资源存储上限 |

### 3.2 展示与提示

| 场景 | 规则 |
| --- | --- |
| 资源区 | 展示当前工作台资源容量使用情况 |
| 上传弹窗 | 展示本次待上传文件大小和上传后预计占用 |
| 接近上限 | 给出提醒，提示用户清理资源或减少上传 |
| 超过上限 | 阻止上传，并说明当前上限、已用容量和本次上传大小 |

### 3.3 上传拦截

| 上传方式 | 规则 |
| --- | --- |
| 普通文件上传 | 上传前校验本次文件大小是否会导致工作台超限 |
| 多文件上传 | 按本次批量文件总大小校验 |
| ZIP 上传 | 按 ZIP 文件大小或解压后文件总大小校验，口径待确认 |
| 文件夹入口上传 | 仍按工作台总容量校验，不只校验目标文件夹 |

说明：

- 工作台容量上限是工作台维度，不是文件夹维度。
- 超限时不应创建部分资源，除非后续明确支持部分成功。
- 用户需要能通过删除资源释放容量。

---

## 4. 本次不做什么

1. 不定义企业级、用户级或项目级总存储配额。
2. 不处理解析结果、分析结果、任务产物的存储上限。
3. 不做自动清理、自动归档或自动压缩。
4. 不做付费扩容、审批扩容或容量申请流程。
5. 不改变现有单文件大小限制。

---

## 5. 验收口径

1. 用户可以在工作台资源区看到当前资源容量使用情况。
2. 用户上传普通文件或多文件时，系统能判断是否会超过工作台资源上限。
3. 上传超过上限时，系统阻止上传并提示已用容量、上限和本次上传大小。
4. 删除资源后，工作台已用容量随之减少。
5. 文件夹不单独计算容量上限，上传到任意文件夹都按工作台总容量校验。
6. ZIP 上传与工作台容量上限之间的校验口径明确后，可以按该口径验收。

---

## 待确认问题

| 问题 | 影响 | 建议 |
| --- | --- | --- |
| 单个工作台资源存储上限是多少 | 影响提示文案和后端限制 | 需与后端 / 部署策略确认 |
| ZIP 上传按压缩包大小还是解压后总大小计入 | 影响上传前校验准确性 | 倾向按解压后有效文件总大小计入 |
| 是否需要展示容量进度条 | 影响资源区 UI 设计 | 待交互设计时确认 |
| 接近上限提醒阈值是多少 | 影响提醒触发时机 | 可先按 80% 或 90% 讨论 |
| 删除资源是否立即释放容量 | 影响回收站 / 软删除设计 | 若存在回收站，需要明确释放时点 |
