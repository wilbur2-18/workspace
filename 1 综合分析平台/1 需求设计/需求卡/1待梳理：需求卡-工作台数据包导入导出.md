# 工作台数据包导入导出

**产品**：综合分析平台  
**状态**：待梳理  
**更新**：2026-05-25  
**关联材料**：工作台资源、结果、任务、上传与解析中文件可用性优化、工作台资源存储上限、批量打包下载任务

---

## 1. 原始需求 / 背景

工作台的整体数据打包：比如不同网段的平台，从专网导出后导入到分析网继续开展工作。分析网的数据权限比专网分析权限更大。

这个需求面向跨网络、跨部署环境的工作台迁移，不是普通文件下载。

---

## 2. 初步理解

审计场景下可能存在多个隔离网段或部署环境。用户在一个环境中完成资料收集、初步整理或部分分析后，需要把整个工作台的数据包导出，再导入到另一个权限更充分、算力或工具能力更强的分析环境中继续工作。

核心问题是：如何把“一个工作台可继续分析所需的对象和上下文”打成可迁移包，并在目标环境恢复为可用工作台。

---

## 3. 目标场景

用户在专网平台中选择一个工作台，导出工作台数据包。数据包通过合规方式转移到分析网后，用户在分析网导入数据包，系统恢复资源、目录、结果和必要的任务上下文，用户可以继续开展分析。

---

## 4. 初步范围

### 4.1 导出内容

首轮需要梳理哪些对象进入工作台数据包：

| 对象 | 初步判断 |
| --- | --- |
| 资源文件 | 需要导出，包括目录结构和文件元数据 |
| 数据库表 | 需区分真实数据、表结构、连接信息或导出快照 |
| 数据图谱 | 需区分图谱实体数据、关系数据和配置 |
| 知识库 | 需区分原始文件、索引结果和关联关系 |
| 技能配置 | 需要导出工作台内引用或配置过的技能副本 |
| 对话记录 | 待确认是否导出，涉及敏感内容和上下文复用 |
| 任务记录 | 待确认是否导出完整记录，至少需要保留产出关系 |
| 分析结果 | 需要导出，包括结果树结构、结果文件和元数据 |

### 4.2 导出 / 导入流程

- 导出时由用户选择工作台，系统生成工作台数据包。
- 数据包生成可能耗时，应作为后台任务进入任务列表。
- 导入时校验数据包完整性、版本兼容性、容量限制和权限。
- 导入成功后生成一个新的工作台，保留原工作台名称或允许用户重命名。
- 导入后资源、结果、技能、任务关系尽量恢复到可继续分析状态。

### 4.3 数据包规则

- 数据包需要包含清单文件，记录包内对象、数量、来源环境、导出时间和版本。
- 数据包应支持完整性校验，避免导入半包或损坏包。
- 跨网段迁移需要考虑脱敏、权限、加密和导入审计日志。
- 目标环境权限更大时，不能默认绕过原数据的安全边界，需要有导入后的权限归属规则。

---

## 5. 影响面与风险

- 与资源存储上限、ZIP 上传、任务监管、批量打包下载任务都有交叉，但本需求对象是“工作台整体迁移包”。
- 数据库表、图谱和知识库是否导出真实数据，会显著影响包大小、安全和导入复杂度。
- 跨网段导入涉及安全合规，需要明确加密、签名、审计日志和导入权限。
- 任务是否可继续执行、是否只保留历史记录，需要单独确认。
- 不同版本平台之间导入导出可能存在兼容性问题。

---

## 待确认问题

| 问题 | 影响 |
| --- | --- |
| 工作台数据包首版是否只覆盖资源和结果，还是覆盖技能、任务、对话、库表、图谱、知识库 | 决定首版范围 |
| 数据库表和图谱导出真实数据还是只导出引用 / 快照 | 影响安全和可用性 |
| 导出包是否必须加密、签名、校验 | 影响跨网段合规 |
| 导入后是恢复原工作台 ID，还是生成新工作台 | 影响任务、结果和引用关系 |
| 导出和导入是否都进入任务列表 | 影响任务监管设计 |
| 目标环境权限更大时，导入后的资源权限如何归属 | 影响安全边界 |
