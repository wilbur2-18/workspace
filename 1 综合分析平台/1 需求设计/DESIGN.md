# Design System: 审计产品线

> 适用范围：本文件定义审计产品线的 UI 设计系统标准。综合分析平台是当前最完整的落地样本，但不是唯一适用边界。本标准可用于综合分析平台、数据图谱平台、数据漫游、智能体平台等审计相关产品和原型。

这是一份“设计语言 + 工程消费契约”。它定义审计产品线 UI 的基本下限、视觉角色、token 使用边界、通用组件契约和产品级 pattern 判断规则。它不逐像素规定每个业务页面，也不阻止新产品根据业务形成新的高质量布局。

本轮标准不依赖任何 `.pen` 文件作为权威来源；当前校准依据是已有 `DESIGN.md`、综合分析平台运行时代码、审查报告和审计产品线的长期产品气质。

## 1. 产品线定位与适用范围

审计产品线面向审计、风控、数据分析和智能辅助工作。界面要帮助用户长期、高频地完成资料治理、数据探索、技能配置、自动分析、对话协同、结果复核和证据追溯。

设计系统的职责：

- 定义跨产品稳定的视觉语言和质量下限。
- 收敛颜色、字号、间距、圆角、阴影和状态表达的可选范围。
- 约束通用组件的基本形态、交互状态和使用边界。
- 为特化业务场景提供 pattern 判断规则，而不是把每个业务布局都组件化。
- 帮助后续原型和页面判断“这个新样式是否仍属于审计产品线”。

设计系统不负责：

- 逐像素规定每个产品、每个页面和每个业务流程。
- 把综合分析平台的全部业务结构直接提升为产品线通用组件。
- 为一次性页面细节新增 token 或新组件。
- 替代具体产品的交互设计、信息架构和业务规则。

## 2. 审计产品线视觉语言

整体气质是“白色工作台 + 企业级审计分析工具”。它不是营销官网，不是数据大屏，也不是纯聊天产品。视觉重心应放在信息结构、状态识别、证据可读性和重复操作效率上。

关键词：

- 白色容器
- 浅灰 / 浅蓝布局
- 蓝色主动作
- 低噪阴影
- 紧凑控件
- 高信息密度
- 清晰状态
- 桌面工作台
- 可复核证据链

产品线 UI 的最低标准：

- 可信：视觉克制、结构稳定、状态清楚，不制造噪音。
- 清晰：用户能快速扫读资料、数据、技能、任务、结果和 AI 对话上下文。
- 高效：搜索、筛选、排序、批量操作、状态汇总和主动作位置稳定。
- 可复用：新增页面优先延续既有 token、组件和 pattern。
- 桌面优先：当前以 1024px 以上桌面视口为主要场景，不假装完成完整移动端适配。

正确的视觉层级：

- 页面外层用浅灰或浅蓝背景建立空间。
- 内容、表格、卡片、弹窗、下拉和聊天容器用白色承载。
- 主色蓝只用于关键动作、选中、链接、焦点和少量关键图标。
- 状态色只用于稳定状态，不扩展成装饰色板。
- 阴影只表达层级，不制造强悬浮感。
- 特化业务场景可以有自己的布局，但不能突破基础色彩、排版、间距、圆角和状态规则。

## 3. Foundation

Foundation 是不可随意突破的产品线基础。新产品、新页面和新组件都应优先消费这些标准；只有跨产品复用、语义稳定、无法映射现有角色时，才允许扩展。

### 3.1 色彩

#### 核心色彩

| Token | 当前基准 | 角色 | 使用场景 |
| --- | --- | --- | --- |

| `--ds-c-success` | `#169c34` | 成功 | 完成、已共享、导入成功、校验通过 |
| `--ds-c-warning` | `#b96b00` | 警告 | 解析中、待处理、需复核、用量偏高 |
| `--ds-c-error` | `#d83a3a` | 错误 | 失败、删除、危险确认、校验错误 |
| `--ds-c-neutral-0` | `#ffffff` | 白色容器 | 卡片、弹窗、表格、下拉、聊天容器 |
| `--ds-c-neutral-2` | `#f5f5f5` | 布局灰 | 页面背景、表头、列表 hover、弱选中 |
| `--ds-c-neutral-4` | `#d4d4d4` | 默认边框 | 输入框、卡片、表格、分割线 |
| `--ds-c-neutral-6` | `#737373` | 弱文字 | meta、placeholder、低优先级辅助信息 |

主色以当前运行时 `#1677ff` 为基准。不要继续使用旧主色锚点，除非后续产品线统一决定并同步修改运行时代码。

#### 语义角色

业务样式优先使用语义 token，而不是直接消费色阶：

| Token | 角色 | 使用方式 |
| --- | --- | --- |
| `--ds-bg-container` | 容器背景 | 页面主体、卡片、弹窗、表格、下拉 |
| `--ds-bg-layout` | 页面背景 | 工作台底色、表头、弱选中和 hover |
| `--ds-bg-sunken` | 内嵌浅底 | meta 区、弱提示、轻量输入底 |
| `--ds-bg-hover-ink` | 弱 hover | 轻量按钮、列表项、非主色 hover |
| `--ds-bg-active-ink` | 弱选中 | 中性选中、轻量激活 |
| `--ds-bg-primary` | 主色面 | 主按钮、少量强主色面 |
| `--ds-bg-primary-hover` | 主色 hover | 主按钮 hover |
| `--ds-bg-primary-soft` | 浅主色底 | 轻量选中、信息提示、主色标签 |
| `--ds-text-1` | 主文字 | 标题、正文、主要按钮、关键数据 |
| `--ds-text-2` | 次文字 | 描述、表格次级信息、统计、辅助标签 |
| `--ds-text-3` | 弱文字 | placeholder、低优先级 meta、空态弱提示 |
| `--ds-text-disabled` | 禁用文字 | disabled、不可操作内容 |
| `--ds-border` | 默认边框 | 输入、卡片、弹窗、表格外边界 |
| `--ds-border-subtle` | 弱边框 | 内部分割、二级容器、表格辅助线 |
| `--ds-border-primary-soft` | 主色弱边框 | 主色轻强调、选中边界 |
| `--ds-fx-focus-ring` | 焦点色 | 键盘焦点、重要聚焦轮廓 |
| `--ds-fx-scrim` | 遮罩 | Modal、Drawer 背景遮罩 |

#### 状态色

状态色统一使用 `--ds-tone-*` 或已有状态 class。不要为单个业务对象临时发明颜色。

- 蓝色：当前、信息、主流程、轻量选中。
- 绿色：完成、成功、已共享、已导入。
- 橙色：待处理、解析中、警告、需复核。
- 红色：失败、删除、危险、校验错误。
- 中性灰：默认、未开始、无特殊状态。
- 紫色：AI、技能、模型、高级能力；只作少量语义点缀。

颜色禁忌：

- 不要在业务样式中裸写新的 `#hex`。
- 不要把主按钮做成渐变。
- 不要把一屏做成大量高饱和状态色。
- 不要用状态色做装饰背景。
- 不要为了隐藏一次性颜色新增 token。

### 3.2 字体与排版

主字体栈：

```css
Inter, -apple-system, system-ui, "Segoe UI", Helvetica,
"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei",
"Noto Sans SC", sans-serif
```

等宽字体只用于代码、配置、JSON、技术参数、CSV / Markdown 预览和需要列对齐的文本。

#### 字阶

| 层级 | Token / Class | 规格 | 使用场景 |
| --- | --- | --- | --- |
| Sub-heading | `--ds-type-subheading-*` | 22px / 600 | 一级页标题、重要弹窗标题 |
| Section Title | `--ds-type-section-title-*` | 20px / 500 | 分区标题、表单区标题 |
| Card Title | `--ds-type-card-title-*` | 18px / 500 | 卡片标题、列表主标题、概览标题 |
| Nav | `--ds-type-nav-*` | 16px / 600 | 主导航、侧栏导航、一级入口 |
| Control LG | `--ds-type-control-lg-*` | 16px / 500 | 大控件、紧凑弹窗分区标题、强操作入口 |
| Body | `.ds-text-body` | 14px / 400 | 默认正文、表单、表格、普通按钮 |
| Caption | `.ds-text-caption` | 14px / 500 | 控件标签、表头、统计、紧凑标题 |
| Caption Light | `.ds-text-caption-light` | 14px / 400 | 描述、摘要、辅助说明 |
| Badge | `.ds-text-badge-label` | 12px / 600 | 标签、状态、表头小字 |
| Micro | `.ds-text-micro` | 12px / 400 | 时间、计数、meta、低优先级信息 |
| Micro XS | `--ds-type-micro-xs-fs` | 10px | 极少数图标几何、角标或非常受限空间 |

排版原则：

- 正文基线是 14px，默认不要降到 13px 或 12px 以下。
- 一级页标题是 22px，不做营销大标题。
- 卡片标题是 18px，描述是 14px。
- 16px 只用于导航、大控件、紧凑模块标题，不作为普通正文。
- 小字统一 12px；10px 只用于图标几何或极少数空间受限标签。
- 字重以 400、500、600 为主，700 只用于极少数强强调数字或必要标识。
- 数字、计数、金额和时间尽量使用 tabular numbers。
- 行高按场景声明，不需要为每个行高重新 token 化。
- 不使用负字距；letter-spacing 只用于极短 uppercase 标签或竖向折叠轨。

### 3.3 版式与栅格

- 根应用以 1024px 最小宽度为现实边界。
- 一级列表页内容最大宽度以 1200px 为基准，居中显示。
- 沉浸式工作区、图谱画布、分析助手、配置编辑器等可以突破 1200px 居中壳。
- 主内容区使用白色容器承载，外层用浅灰或浅蓝背景建立层次。
- 页面滚动应集中在主内容区，避免 body 与内部容器双滚动。
- 页面 section 不要全部卡片化；卡片只用于重复项、弹窗和工具面板。
- 不要为了“高级感”增加大留白，影响扫读效率。

### 3.4 间距

| Token | 值 | 使用场景 |
| --- | --- | --- |
| `--ds-space-xxs` | 4px | 图标与文字、tag 内部、紧凑 meta |
| `--ds-space-xs` | 8px | 控件组、小间距、侧栏 padding |
| `--ds-space-sm` / `--ds-space-s` | 12px | 工具条、按钮组、列表内部 |
| `--ds-space-m` | 24px | 页面 padding、卡片网格、段落间距 |
| `--ds-space-2xl` | 32px | 大控件组、宽面板内部节奏 |
| `--ds-space-l` | 40px | 大区块、宽松弹窗段落 |
| `--ds-space-xl` | 60px | 少量展示型留白 |

间距原则：

- B 端主节奏以 8 / 12 / 24 为主。
- 4px 用于图标与文字、tag 内部、紧凑 meta。
- 10px、14px、16px、18px 等值只应作为布局几何或特定 pattern 的局部需要，不应扩散成通用节奏。
- 侧栏、树、表格、资料列表可以紧凑，但点击区域不能过小。

### 3.5 圆角

| Token | 值 | 使用场景 |
| --- | --- | --- |
| `--ds-radius-micro` | 4px | 小按钮、小标签、细小控件 |
| `--ds-radius-control` | 6px | 输入框、触发按钮、普通控件 |
| `--ds-radius-standard` | 8px | 小卡、表格壳、内联面板 |
| `--ds-radius-md` | 12px | 标准卡片、主容器、Modal |
| `--ds-radius-lg` | 16px | 聊天气泡、少量强调容器 |
| `--ds-radius-pill` | 9999px | 标签、状态 pill、segmented |

圆角原则：

- 主要卡片和容器使用 8px 或 12px。
- 16px 只用于少量强调容器、聊天气泡或产品级 pattern 明确要求的场景。
- 24px 以上只适用于 pill，不用于普通卡片。
- 不要把所有卡片做成大圆角。

### 3.6 阴影与深度

| 层级 | Token | 使用场景 |
| --- | --- | --- |
| Flat | none | 页面底、普通文本区、工具条 |
| Border | `1px solid var(--ds-border)` | 输入、表格、卡片边界 |
| Soft | `--ds-shadow-sm` | 轻浮层、微弱 hover |
| Card | `--ds-shadow-card` | 标准卡片、主内容壳、列表卡 |
| Deep | `--ds-shadow-deep` | Modal、Drawer、重要浮层 |
| Focus | `--ds-shadow-focus-primary` | 键盘焦点、重要聚焦 |

阴影原则：

- 阴影只表达层级，不制造悬浮表演。
- 卡片 hover 可以轻微提升边框、背景或阴影，不放大、不旋转。
- 业务 CSS 不应拼接新的大阴影；确有浮层需求时优先使用现有 shadow token。
- 动画光晕、pulse、引导态属于特化 pattern，必须轻量、短暂、可解释。

### 3.7 z-index、动效与图标

z-index 应使用产品线层级 token 或已有组件层级：

- 基础内容：`--ds-z-base`
- 局部面板：`--ds-z-panel`
- 局部 popover：`--ds-z-popover-local`
- dropdown：`--ds-z-dropdown`
- 全屏态：`--ds-z-fullscreen`
- nested modal：`--ds-z-modal-nested`
- 工作区侧栏 / 嵌入态：使用对应 workbench token

不要随意写 `10 / 25 / 1110 / 3100` 等裸 z-index，除非它是明确的局部几何例外并已有注释说明。

动效应短、轻、稳定：

- 常规反馈使用 `--ds-transition-fast`。
- 大面板展开、抽屉、工作区切换可使用 `--ds-transition-smooth`。
- 不做大幅缩放、旋转、弹跳或装饰性动效。

图标原则：

- 工具按钮优先使用图标 + 清晰 tooltip 或短文本。
- 图标大小使用 `--ds-type-icon-*` 或组件默认尺寸。
- 图标按钮点击区域不小于 28px。
- 不用图标代替必须阅读的状态说明。

## 4. Token 分层与消费规则

审计产品线 token 分四层。新增样式时必须先判断属于哪一层。

### 4.1 Primitive

Primitive 是基础材料，如色阶、RGB channel、字体族、基础间距、圆角、阴影刻度。

规则：

- 只在 foundation 或 token 定义层直接消费。
- 业务 CSS 不应直接绑定到某个色阶，除非没有对应 semantic token。
- 不要删除 primitive token，只因为当前页面没有直接使用。

### 4.2 Semantic

Semantic 是业务样式的首选入口，如背景、文字、边框、状态、focus、scrim。

规则：

- 新业务样式优先使用 semantic token。
- 不要直接写裸色、裸阴影或临时字号。
- 状态必须使用稳定语义，不为单个对象随机配色。

### 4.3 Component

Component token 服务具体组件，如按钮、标签、输入、trigger、pill、tree、popover、list card。

规则：

- Component token 只服务对应组件或明确同源变体。
- 不要把组件 token 当全局布局 token 使用。
- 不要为了一个页面的特殊值新增组件 token。

### 4.4 Context

Context token 服务产品级场景，如一级页面 hero、沉浸式工作区、分析助手、图谱画布等。

规则：

- Context token 可以表达产品气质和场景差异。
- 新增 context token 必须有稳定场景和复用价值。
- 综合分析平台的特化场景不能自动变成产品线通用 context。

## 5. 通用组件契约

通用组件定义跨产品稳定规则。实现可以是 Vue 组件、Ant Design Vue 组件、CSS class 原语或本地 wrapper；文档关注行为和视觉契约，不要求所有场景都必须封装成同一种技术形态。

### 页面壳与 Hero

- 一级列表页使用页面壳承载内容，最大宽度以 1200px 为基准。
- 标题区使用产品线 hero 模式，标题 22px / 600，副标题 14px / 400。
- Hero 只说明当前模块和主要价值，不写营销文案。
- 沉浸式工作区、图谱画布、分析助手不强行套一级页 hero。

### 导航与应用壳

- 顶部或侧边导航使用 16px / 600。
- 当前模块用主色蓝表达。
- 导航只承载稳定一级入口，不塞临时业务筛选。
- 用户、设置、更多等辅助动作保持低噪。

### 信息控制轨

- 搜索、筛选、排序、总数、展示切换、批量状态应组织在稳定控制轨内。
- 筛选和排序入口使用 trigger button，优先 icon + text。
- 不要把筛选、排序做成大号主按钮。
- 控制轨应支持长文本、空状态和批量选择状态。

### 按钮

- 主按钮只用于创建、保存、上传、确认、执行等主流程动作。
- 主按钮使用纯主色，不使用渐变。
- 次操作使用默认按钮、浅灰按钮或 link button。
- 普通按钮不应依赖加粗来表达层级；优先用位置、颜色、边框和尺寸。
- 更多、返回、收起、筛选、排序、上传、搜索等操作应使用清晰图标。

### 输入与表单

- 输入、选择、日期、文本域优先使用 Ant Design Vue 或产品线 wrapper。
- 默认控件高度 32px，页面主 CTA 40px。
- focus 必须清晰可见。
- placeholder 使用弱文字，不替代标签。
- 表单说明和错误提示紧贴字段，不散落在页面底部。

### 标签与状态

- 标签用于分类、范围、文件类型、技能特征，不承担长文本说明。
- 筛选标签应有 active / hover / disabled 形态。
- 状态使用状态 pill 或同源状态 class，适合“完成 / 失败 / 已共享 / 解析中”等短状态。
- 状态色必须有稳定语义。

### 表格

- 表格用于资料列表、结果列表、配置清单、审计发现明细和数据记录。
- 表格外层白底、8px 圆角、默认边框。
- 表头使用浅灰底和 12px / 600 文案。
- 单元格保持 8px / 12px 的紧凑 padding。
- 操作列使用 link button 或紧凑 icon button，不塞多个主按钮。
- 数字、金额、时间、计数使用等宽数字。

### Modal 与 Drawer

- Modal 用于创建、编辑、确认、预览、版本详情等聚焦任务。
- Modal 内容区使用 12px 圆角、深浮层阴影和遮罩。
- Footer 主操作靠右，取消 / 次操作在主操作左侧或按产品线统一 footer 规则排列。
- Drawer 用于辅助信息、详情预览、配置面板，不替代主流程表单。
- 宽内容必须不超出视口，内容区可滚动。
- 页面内折叠资源栏、侧栏和分栏面板不自动等同于 Drawer。

## 6. 产品级 Patterns

Pattern 是跨页面或跨产品复用的业务结构。它比通用组件更具体，但仍不应绑定某个产品的所有业务细节。

### 工作台 Pattern

适用于项目、任务、审计空间、分析空间等入口。

- 使用一级页面 hero + 控制轨 + 卡片 / 表格列表。
- 卡片白底、低噪阴影、8px 或 12px 圆角。
- 主动作位置稳定，通常在右上。
- 卡片只承载核心摘要、状态、统计和进入动作。
- 不把工作台做成营销 landing page。

### 分析助手工作区 Pattern

适用于审计助手、智能问答、分析协同等对话式工作区。

- 推荐三栏或多栏桌面工作区：左侧资源 / 技能，中间对话 / 推理，右侧任务 / 结果 / 证据。
- 中间对话保持可读宽度，避免单行过长。
- 用户气泡使用浅主色，AI 回复使用白底和清晰文本层级。
- 工具调用、思考、引用、diff、结果预览保持白底、浅边框、紧凑工具条。
- 右侧结果区使用卡片、表格或列表，不做黑色控制台。
- 资源、任务、结果的状态必须可扫读、可追踪、可复核。

综合分析平台的审计助手是当前参考实现，但其他产品不需要逐字复刻三栏结构。

### 资料与结果管理 Pattern

适用于文件、数据表、图谱节点、报告、分析结论和证据材料。

- 支持搜索、筛选、排序、状态筛选和批量操作。
- 文件类型、数据类型、结果类型使用稳定图标和标签。
- 解析中、失败、完成、待复核等状态语义一致。
- 结果和证据应保留来源、时间、生成方式和复核状态。
- 长文本和复杂结果优先提供预览、展开、复制、下载或引用入口。

### 图谱画布 Pattern

适用于关系图、实体图谱、资金流、业务链路等可视分析。

- 画布可以沉浸式铺开，不受 1200px 内容宽度限制。
- 工具栏、筛选器、详情面板使用产品线控件和 token。
- 节点和边的颜色必须绑定稳定语义，不把状态色当装饰色。
- 右侧详情、底部时间线、局部浮层应遵守阴影和 z-index 规则。
- 图谱高亮必须清楚但克制，避免大面积高饱和颜色。

### 配置编辑器 Pattern

适用于技能配置、规则配置、模板配置、字段映射等高密度编辑场景。

- 可以使用双栏或三栏结构。
- 左侧树 / 列表负责导航和对象选择，中间 / 右侧负责编辑和预览。
- 保存、校验、dirty、错误、禁用状态必须明确。
- 配置说明和错误提示紧贴对应字段。
- 复杂配置可以使用 16px control-lg 标题，但正文仍保持 14px 基线。

## 7. 例外机制

允许业务特化，但必须满足以下条件：

- 仍使用产品线 semantic token。
- 不新增裸色、裸阴影、临时字号或非系统圆角。
- 不破坏控件高度、文字层级、状态色语义和焦点可见性。
- 特化值是布局几何、图标几何、画布约束或业务 pattern 需要，而不是跳过 token。
- 同类结构第二次出现时，应评估是否沉淀为 pattern。
- 跨产品复用且语义稳定时，才考虑新增 token 或组件。

不允许的例外：

- 为单个页面的一次性视觉新增 token。
- 为了“高级感”引入大渐变、玻璃拟态、装饰光斑或过度留白。
- 把主按钮改成渐变。
- 把状态色扩展成装饰色板。
- 把综合分析平台某个业务结构直接规定为全产品线必须复刻。

## 8. 验证口径

### 文档范围验收

- 文档归属审计产品线，而不是某个单一产品。
- 综合分析平台被描述为当前参考实现，不是唯一标准来源。
- 文档不依赖 `.pen` 文件作为本轮判断来源。
- 文档不把综合分析平台专有业务名词写成产品线通用组件。

### 一致性验收

- 主色使用 `#1677ff`。
- 主文字入口为 `--ds-text-1`，当前映射到 `--ds-c-neutral-9`。
- 字阶覆盖 22 / 20 / 18 / 16 / 14 / 12。
- 间距以 8 / 12 / 24 为主要节奏。
- 主要卡片和容器使用 8px 或 12px 圆角。
- 阴影使用现有层级，保持低噪。

### 原型验证

综合分析平台是当前首个验证样本。默认检查：

- `demo.html#project`：一级页 hero、信息控制轨、卡片网格、主按钮符合标准。
- `demo.html#template`：技能库延续同一 L1 页面语言。
- `demo.html#freeaudit?projectId=PRJ-2026-001`：分析助手工作区符合产品级 pattern，不按普通 L1 居中页审查。

后续抽样其他产品原型时，只检查 foundation、通用组件和适用 pattern，不要求复刻综合分析平台页面结构。

### 治理检查

综合分析平台当前检查入口：

```bash
node scripts/check-manifest.js
```

检查应至少守住：

- Chrome 109 兼容颜色写法。
- 业务 CSS 不出现裸 `#hex`。
- 不使用旧 token。
- token coverage 保持 `should-fix=0`。

其他产品同步产品线设计系统时，应建立自己的检查入口，不硬拷贝综合分析平台业务 CSS。

## 9. AI Agent 使用守则

当 Codex、Cursor 或其它 agent 修改审计产品线原型 UI 时，必须遵守以下规则。

### 优先级

1. 先读本文件，理解审计产品线视觉语言。
2. 再读目标产品目录 README、AGENTS 和运行入口。
3. 再读现有页面和组件，复用当前 class、token 和 pattern。
4. 最后才新增样式；新增样式必须能被本设计系统解释。

### 必须做

- 使用 `--ds-*` token 表达颜色、字号、间距、阴影、圆角。
- 优先复用现有组件、class 原语和产品级 pattern。
- 保持 14px 正文基线、32px 默认控件、40px 主 CTA。
- 保持桌面优先和 1024px 最小宽度现实。
- 为 hover、focus-visible、selected、disabled、loading、empty 提供清晰状态。
- 对特化布局说明它属于哪个 pattern，或为什么是局部几何例外。

### 不要做

- 不要裸写新颜色、临时字号、临时间距和临时阴影。
- 不要把主按钮改成渐变。
- 不要新增紫蓝大渐变、玻璃拟态、装饰光斑或插画式首页。
- 不要把工作台改成营销 landing page。
- 不要为单个模块复制一套按钮、标签、表格、弹窗样式。
- 不要把页面 section 全部做成卡片。
- 不要假装已经完成移动端适配。

### 判断标准

新增 UI 合格的最低标准：

- 颜色角色清楚，主色只服务关键动作和状态。
- 字号落在产品线字阶内。
- 间距以 8 / 12 / 24 为主要节奏。
- 卡片和容器使用 8px 或 12px 圆角。
- 阴影轻，不抢内容。
- 搜索、筛选、排序、批量操作位置稳定。
- 表格、资料树、卡片、弹窗、画布面板都能快速扫读。
- AI / 智能分析区域像审计工作台，不像聊天娱乐网站。
