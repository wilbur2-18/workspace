# 综合分析平台

综合分析平台是面向审计业务的工作台化分析平台，通过资料、技能、助手和结果沉淀，帮助用户完成从审计资料治理到分析结论复核的闭环。

## 产品判断

当前重点不是做一个通用 AI 聊天工具，而是围绕审计任务形成“资料输入 - 技能执行 - 助手协同 - 结果沉淀”的业务闭环。

## 核心抓手

- 工作台：承载单个审计任务的业务容器。
- 技能：可复用的分析方法和执行配置。
- 审计助手：对话式协同分析入口。
- 分析结果：沉淀结论、过程和证据。

## 目录角色

| 目录 | 作用 |
| --- | --- |
| `0 产品文档` | 产品介绍、对外材料、PPT 内容稿等。 |
| `1 需求设计` | 需求卡目录、设计约束、高保真原型和版本说明。需求卡通过 `需求卡/需求台账.html` 集中管理。 |
| `x 产品文档` | 迁移或待整理的产品资料。 |
| `x 历史备份` | 原型或资料备份包。 |
| `x 杂七杂八` | 临时分析、架构梳理、材料汇总、申报材料和一次性讨论产物。按事项独立建文件夹。 |

目录名可能随工作推进调整。处理任务时以当前文件系统和附近 README 为准。

## 归类边界

- `1 需求设计` 只放需求卡、设计约束、高保真原型、原型版本说明，以及与需求 / 原型交付直接相关的材料。
- 与原型设计无关的临时分析、架构讨论稿、材料汇总、一次性 HTML / Markdown 产物，放入 `x 杂七杂八/<事项>/`。
- `x 杂七杂八` 下不要直接散放文件；每个事项建立独立文件夹，必要时在事项文件夹内补一个简短 `README.md` 说明来源和用途。
