# 政务审计系统操作手册写作规范

## 1. 写作目标

政务审计系统操作手册应帮助审计人员快速理解系统的适用场景、操作路径、完成标志、结果复核方式和异常处理方法。

手册的核心不是介绍系统有哪些功能，而是帮助审计人员完成审计工作中的具体任务。

操作手册应回答以下问题：

- 什么时候使用这个功能？
- 使用前需要满足什么条件？
- 从哪里进入？
- 按什么步骤操作？
- 如何判断操作成功？
- 操作结果如何复核、留痕或导出？
- 出现异常时如何处理？

## 2. 读者定位

### 2.1 主要读者

- 一线审计人员
- 审计项目组成员
- 审计业务管理人员
- 培训交付人员
- 需要了解系统使用路径的实施和运维人员

### 2.2 读者假设

默认读者了解审计业务，但不一定了解系统实现、数据处理机制或人工智能技术细节。

因此，手册应使用审计人员能理解的业务语言，避免使用研发实现语言。

不推荐直接使用：

- 接口
- 组件
- 队列
- 缓存
- 调度器
- 模型链路
- 后端服务

如确需说明，应转换为业务表达。

示例：

| 不推荐 | 推荐 |
| --- | --- |
| 系统进入异步队列 | 任务已提交，系统将按顺序执行 |
| 调用模型失败 | 分析任务未能生成结果 |
| 接口返回异常 | 页面未能获取到最新数据 |
| 后端解析中 | 系统正在读取资料内容 |

## 3. 总体写作原则

### 3.1 任务导向

手册应按审计人员要完成的任务组织，而不是按菜单、页面或按钮从上到下罗列。

推荐章节命名：

- 创建审计项目
- 上传审计资料
- 发起资料分析
- 查看任务进度
- 复核分析结果
- 导出审计成果

不推荐章节命名：

- 首页介绍
- 左侧菜单说明
- 按钮说明
- 字段说明
- 页面功能介绍

### 3.2 先场景，后步骤

每个操作章节应先说明适用场景，再说明操作步骤。

审计人员需要先知道“为什么要做”，再看“怎么做”。

推荐结构：

```md
## 上传审计资料

### 适用场景
当审计人员需要将合同、凭证、会议纪要、制度文件等资料纳入系统分析时，使用本功能。

### 前置条件
已进入对应审计项目，并具备资料上传权限。

### 操作步骤
1. 进入项目工作台。
2. 点击“上传资料”。
3. 选择需要上传的本地文件。
4. 确认文件名称和分类。
5. 点击“开始上传”。

### 完成标志
资料出现在资料列表中，且状态显示为“解析完成”或“可使用”。
```

### 3.3 过程可追踪

政务审计场景强调过程留痕和依据追溯。手册不能只写“系统生成结果”，还应说明结果从哪里来、如何复核、如何导出或归档。

涉及分析结果、疑点识别、风险提示时，应说明：

- 结果引用了哪些资料
- 是否能查看原文片段
- 是否能查看生成任务
- 是否能查看执行时间
- 是否能编辑、确认、驳回或重新生成
- 是否能导出为底稿、报告或附件

### 3.4 人工判断优先

涉及智能分析、自动识别、模型生成内容时，应明确系统提供辅助分析，最终判断由审计人员结合审计程序和专业判断完成。

推荐表述：

> 系统生成的分析结果用于辅助审计判断。审计人员应结合原始资料、审计程序和专业判断进行复核确认。

避免表述：

> 系统自动判断违规。  
> 系统可以发现全部问题。  
> 生成结果可直接作为审计结论。  

### 3.5 权限差异显式说明

不同单位、项目、角色和部署环境下，用户可见功能可能不同。手册应说明权限差异，避免写死所有用户均可执行的操作。

推荐表述：

> 实际可见的项目、资料、功能入口和操作按钮，以本单位部署配置和当前账号权限为准。

不推荐表述：

> 所有用户均可删除资料。  
> 每个用户都可以进入系统管理。

## 5. 单个操作章节格式

每个操作章节建议统一使用以下格式。

```md
## 操作名称

### 适用场景
说明什么时候需要使用该功能。

### 前置条件
说明使用该功能前需要满足的条件。

### 操作入口
说明从哪里进入该功能。

### 操作步骤
使用编号列表描述操作，一步只写一个动作。

### 完成标志
说明用户如何判断操作已经完成。

### 注意事项
说明权限、数据、安全、限制和异常情况。
```

### 5.1 适用场景

适用场景应从审计任务出发，说明该功能解决什么业务问题。

推荐：

> 当审计人员需要对被审计单位提供的合同、付款凭证和验收材料进行集中分析时，可先上传资料并等待系统完成解析。

不推荐：

> 本功能用于上传文件。

### 5.2 前置条件

前置条件应写清用户执行操作前必须具备的条件。

常见前置条件包括：

- 已登录系统
- 已进入审计项目
- 已具备相应权限
- 已准备待上传资料
- 已完成资料解析
- 已选择分析对象
- 当前任务已执行完成

### 5.3 操作入口

操作入口应说明用户从哪里进入功能。

推荐：

> 在项目工作台中，点击页面右上角“上传资料”。

不推荐：

> 点击按钮进入。

### 5.4 操作步骤

操作步骤应使用编号列表。每一步只写一个动作。

推荐：

```md
1. 进入“项目工作台”。
2. 点击“上传资料”。
3. 在弹窗中选择需要上传的文件。
4. 确认文件名称和资料分类。
5. 点击“开始上传”。
```

不推荐：

```md
进入项目后点击上传资料并选择文件然后开始上传。
```

### 5.5 完成标志

完成标志应告诉用户如何判断操作成功。

推荐：

> 资料出现在资料列表中，状态显示为“解析完成”，表示该资料可以用于后续分析。

不推荐：

> 上传完成。

### 5.6 注意事项

注意事项只写与当前操作强相关的限制、风险和异常。

推荐：

> 删除资料前，请确认该资料未被正在执行的分析任务使用。删除后，相关任务可能无法继续查看原始依据。

不推荐：

> 请谨慎操作。

## 6. 操作步骤写法规范

### 6.1 使用界面原词

按钮、菜单、页签、状态、弹窗名称应与系统界面保持一致，并使用中文引号标识。

示例：

- 点击“创建任务”
- 切换到“分析结果”页签
- 状态显示为“解析中”
- 在“选择资料”弹窗中勾选文件

### 6.2 动词要具体

少用抽象动词，多用具体操作动词。

推荐：

- 选择资料
- 填写任务名称
- 勾选分析范围
- 查看引用依据
- 下载结果文件
- 重新执行任务

不推荐：

- 处理资料
- 配置内容
- 管理结果
- 操作数据

### 6.3 一句话只表达一个操作

复杂操作应拆成多个步骤，不要在一个句子中连续堆叠多个动作。

推荐：

```md
1. 选择需要分析的资料。
2. 选择分析技能。
3. 填写任务名称。
4. 点击“提交任务”。
```

不推荐：

```md
选择资料和技能并填写任务名称后提交。
```

### 6.4 状态变化要写清

如果操作后系统会进入某种状态，应说明状态含义。

示例：

| 状态 | 含义 | 用户可执行操作 |
| --- | --- | --- |
| 排队中 | 任务已提交，等待系统执行 | 等待或取消任务 |
| 运行中 | 系统正在执行分析 | 查看进度 |
| 已完成 | 系统已生成分析结果 | 查看、复核或导出结果 |
| 失败 | 任务未能生成结果 | 查看原因并重新执行 |

## 7. 表格使用规范

表格适合用于表达结构化信息，但不应替代操作步骤。

适合使用表格的内容：

- 状态说明
- 权限差异
- 字段填写说明
- 操作对象与可执行动作
- 异常原因与处理方式
- 结果类型与使用方式

### 7.1 字段说明表

```md
| 字段 | 是否必填 | 填写说明 |
| --- | --- | --- |
| 任务名称 | 是 | 建议使用审计事项或资料名称，便于后续查找 |
| 分析资料 | 是 | 选择本次任务需要引用的资料 |
| 备注 | 否 | 可填写任务目的或补充说明 |
```

### 7.2 异常处理表

```md
| 异常情况 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 上传失败 | 文件格式不支持或网络中断 | 检查文件格式后重新上传 |
| 解析失败 | 文件内容无法识别或文件损坏 | 更换文件或联系管理员 |
| 无权限访问 | 当前账号未被授权 | 联系项目管理员确认权限 |
```

## 8. 截图规范

截图应服务于操作理解，不应堆砌页面全貌。

### 8.1 截图使用原则

- 优先截取关键操作区域，不默认整页截图。
- 截图应与正文步骤对应。
- 截图中文字应清晰可读。
- 截图中应避免出现真实敏感信息。
- 同一流程中的截图编号应连续。
- 截图下方应有简短说明。

### 8.2 截图标注格式

```md
> 截图 4-1：上传资料入口  
> 建议截取区域：项目工作台右上角操作区  
> 需突出内容：“上传资料”按钮
```

### 8.3 脱敏要求

截图中如出现以下信息，应遮挡或替换：

- 真实姓名
- 真实单位名称
- 真实项目名称
- 身份证号、手机号、账号
- 银行账号、合同编号、发票号码
- 内网地址、服务器地址
- 敏感金额
- 未公开审计事项

## 9. 政务审计场景特别要求

### 9.1 审计结论不能由系统替代

手册中凡涉及智能分析、风险识别、疑点提示、自动生成结论的内容，均应强调人工复核。

推荐：

> 系统生成的疑点用于辅助审计人员定位重点事项，审计人员应结合原始资料、审计程序和专业判断进行确认。

避免：

> 系统自动确认疑点。  
> 系统自动形成审计结论。  

### 9.2 结果必须说明依据追溯方式

涉及结果查看的章节，应说明如何回到依据材料。

应写清：

- 如何查看引用资料
- 如何查看原文片段
- 如何查看生成该结果的任务
- 如何查看生成时间
- 如何下载或归档结果
- 如何处理结果不准确的情况

### 9.3 保持正式克制的语言

政务审计系统手册应使用正式、清晰、克制的表达，不使用营销化或夸张表达。

推荐：

- 系统辅助识别疑点。
- 审计人员可查看引用依据。
- 任务执行完成后，可在结果列表中查看分析结果。
- 如长时间未生成结果，可联系管理员确认任务执行情况。

避免：

- 一键发现所有风险。
- 轻松搞定审计分析。
- 智能秒出结论。
- 用户随便上传即可。

### 9.4 保留业务语义

示例数据和说明应保留审计业务语义，不能写成过度抽象的测试数据。

推荐：

- 某建设项目合同
- 某单位付款凭证
- 会议纪要
- 供应商清单
- 投资项目可行性研究报告

不推荐：

- 文件 1
- 测试资料
- 示例数据
- demo 文件

## 10. 常见章节示例

### 10.1 上传审计资料

```md
## 上传审计资料

### 适用场景
当审计人员需要将合同、凭证、会议纪要、制度文件、项目资料等材料纳入系统分析时，使用本功能。

### 前置条件
已登录系统，已进入对应审计项目，并具备资料上传权限。

### 操作入口
在项目工作台中，点击“上传资料”。

### 操作步骤
1. 进入“项目工作台”。
2. 点击“上传资料”。
3. 在弹窗中选择需要上传的文件。
4. 确认文件名称和资料分类。
5. 点击“开始上传”。
6. 等待系统完成上传和解析。

### 完成标志
资料出现在资料列表中，状态显示为“解析完成”，表示该资料可以用于后续分析。

### 注意事项
上传资料前，应确认文件内容与当前审计项目相关。涉及敏感信息的资料，应按照本单位数据安全要求处理。
```

### 10.2 发起分析任务

```md
## 发起分析任务

### 适用场景
当审计人员需要基于指定资料执行比对、提取、核查或风险识别时，使用本功能。

### 前置条件
已进入审计项目，待分析资料已上传并解析完成。

### 操作入口
在项目工作台中，进入“分析任务”或“审计助手”，点击“创建任务”。

### 操作步骤
1. 点击“创建任务”。
2. 填写任务名称。
3. 选择需要使用的分析能力。
4. 勾选本次任务需要引用的资料。
5. 确认任务说明。
6. 点击“提交任务”。

### 完成标志
任务出现在任务列表中，状态显示为“排队中”“运行中”或“已完成”。

### 注意事项
任务提交后，系统将按顺序执行。任务执行时间与资料数量、资料大小和系统资源有关。
```

### 10.3 查看和复核分析结果

```md
## 查看和复核分析结果

### 适用场景
当分析任务执行完成后，审计人员需要查看系统生成的分析结果，并结合原始资料进行复核。

### 前置条件
分析任务已完成，并已生成结果。

### 操作入口
在项目工作台中，进入“分析结果”列表，点击需要查看的结果。

### 操作步骤
1. 进入“分析结果”列表。
2. 点击需要查看的结果名称。
3. 阅读系统生成的分析内容。
4. 查看结果引用的资料和原文片段。
5. 结合审计程序和专业判断进行复核。
6. 根据复核情况，对结果进行确认、修改、下载或归档。

### 完成标志
审计人员已完成结果复核，并明确该结果是否可作为后续审计分析、底稿整理或报告撰写的参考。

### 注意事项
系统生成的分析结果仅作为辅助依据，不替代审计人员的专业判断。
```

## 11. 语言风格规范

### 11.1 推荐表达

- “审计人员可在结果详情中查看引用依据。”
- “如任务长时间处于排队状态，可联系管理员确认系统资源情况。”
- “删除资料前，请确认该资料未被正在执行的任务使用。”
- “实际可见功能以当前账号权限为准。”
- “系统生成结果后，审计人员应结合原始资料进行复核。”

### 11.2 避免表达

- “轻松搞定”
- “一键智能发现所有风险”
- “超级强大的 AI 分析”
- “用户随便上传即可”
- “系统自动判断违规”
- “结果可以直接作为审计结论”

## 12. 交付检查清单

操作手册交付前，应逐项检查以下内容：

- 是否按审计任务组织，而不是按菜单堆功能。
- 每个操作章节是否包含适用场景、前置条件、操作入口、操作步骤、完成标志和注意事项。
- 操作步骤是否一条只写一个动作。
- 按钮、菜单、页签、状态名称是否与系统界面一致。
- 是否说明权限差异。
- 是否说明数据脱敏要求。
- 是否说明智能分析结果需要人工复核。
- 是否写清结果依据和追溯方式。
- 是否写清异常状态和处理方式。
- 截图是否清晰、脱敏、指向明确。
- 是否避免技术实现语言。
- 是否避免夸大承诺。
- 是否保留政务审计业务语义。

## 13. 推荐统一模板

后续编写具体操作章节时，可直接使用以下模板。

```md
## 功能或操作名称

### 适用场景
说明审计人员在什么业务情况下需要使用该功能。

### 前置条件
- 已登录系统。
- 已进入对应审计项目。
- 已具备相关操作权限。
- 已准备所需资料或数据。

### 操作入口
说明从哪个页面、哪个区域、哪个按钮进入。

### 操作步骤
1. 第一步操作。
2. 第二步操作。
3. 第三步操作。

### 完成标志
说明用户如何判断操作成功，例如状态变化、列表新增记录、结果生成、文件下载完成等。

### 结果复核
说明用户如何查看依据、原文、任务记录、生成时间和操作留痕。

### 注意事项
- 权限差异说明。
- 数据安全说明。
- 操作限制说明。
- 异常处理提示。
```
