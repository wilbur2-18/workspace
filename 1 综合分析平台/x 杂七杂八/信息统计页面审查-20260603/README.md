# 信息统计页面审查

**日期**：2026-06-03  
**范围**：综合分析平台原型 `demo.html#settings` 中的系统管理 / 信息统计页面。  
**参照材料**：`1 需求设计/需求卡/3待开发：需求卡-用户用量统计.md`。  
**方式**：本地静态服务 + headless Chrome CDP 截图审查。未修改原型代码。

## 截图步骤

1. `01-default-desktop.png`：桌面默认态，最近 1 月、全部组织。
2. `02-org-filter-open.png`：统计组织选择器展开态。
3. `03-org-row-selected.png`：点击“经济责任审计处”后，用户榜单联动态。
4. `04-mobile.png`：390px 窄屏视口。

## 整体判断

页面主结构已经对齐“按时间 + 组织范围查看 Token 用量”的核心目标：顶部筛选、汇总卡、组织用量表、用户消耗榜单都能形成闭环。当前主要问题不是缺少大功能，而是统计口径、联动状态和响应式表现没有解释清楚，容易让管理员误读数据范围。

## 亮点

1. 顶部筛选和刷新集中在页头，默认态能快速看出当前时间范围是“最近1月”。
2. 四个核心指标没有引入复杂图表，符合首版聚焦 Token 用量的范围。
3. 组织表和用户榜单并排，点击组织后右侧榜单能即时收窄到对应组织，路径短。
4. 组织选择器使用树形结构，并提供搜索输入，符合按组织范围筛选的场景。

## 主要风险

1. **页面命名过泛**  
   证据：`01-default-desktop.png`。页面标题和菜单均为“信息统计”，但页面实际只统计大模型 Token、调用、活跃组织和活跃用户。管理员可能期待资源上传量、任务数、结果数等更宽泛统计。建议标题改为“用量统计”或在标题下补一句“统计大模型调用用量”。

2. **顶部汇总是否受组织范围影响不够明确**  
   证据：`01-default-desktop.png`、`02-org-filter-open.png`。需求口径是顶部汇总只受时间范围影响，不随统计组织范围切换；当前 UI 没有显式说明。用户选择某个组织后，可能误以为顶部四张卡也会变成该组织数据。建议在汇总区标题或卡片 tooltip 中明确“平台汇总，仅受时间范围影响”。

3. **组织筛选和组织行点击是两个不同状态，但视觉区分偏弱**  
   证据：`03-org-row-selected.png`。顶部仍显示“全部组织”，左表标题也显示“全部组织 用量统计”，右表标题变为“经济责任审计处 用户消耗榜单”。这符合需求规则，但用户不一定理解“顶部筛选范围”和“行点击临时联动范围”的差异。建议在右侧榜单标题旁展示可关闭的范围 chip，例如“当前榜单：经济责任审计处及下级”，并把“取消选中”放到这个 chip 或右侧榜单区域。

4. **组织表下半屏空白过大，页面完成感不足**  
   证据：`01-default-desktop.png`。桌面 1600x1000 下，组织表只有 4 行，但面板拉满到页面底部，左侧出现大量空白。建议降低组织表面板的最小高度，或在组织表下方放统计口径说明、最近更新时间、导出范围说明等轻量信息。

5. **多组织用户与汇总不可相加的规则没有在页面中显性提示**  
   证据：`01-default-desktop.png`。组织表展示“本组织及下级组织”的说明，但没有说明多组织用户可能导致跨组织相加大于顶部平台总量。建议在组织表标题 tooltip 中补充“多组织用户会在命中组织分别计入，组织行不可直接相加”。

6. **用户榜单缺少账号信息，重名场景识别风险高**  
   证据：`01-default-desktop.png`。需求字段是“用户姓名 / 账号”，当前只展示姓名和组织。政府客户中重名、跨组织兼职都可能存在。建议用户列展示“姓名 + 账号”，组织作为次级信息保留。

7. **行点击联动缺少可发现性和可访问性信号**  
   证据：`01-default-desktop.png`、`03-org-row-selected.png`。组织行看起来像普通表格行，用户不容易知道点击会改变右侧榜单；截图无法证明键盘可聚焦。建议增加行 hover/选中说明，或在组织列增加“查看用户”轻量动作；实现上为可点击行提供键盘焦点、`aria-selected` 和明确的状态变化提示。

8. **导出范围不透明**  
   证据：两个表都有“导出”按钮，但页面未说明组织导出不受展开状态影响、用户导出不受分页影响。建议给导出按钮增加 tooltip 或点击前确认文案，说明当前导出的范围。

9. **窄屏/缩放韧性不足**  
   证据：`04-mobile.png`。390px 视口下页面不是重排，而是横向裁切：页头筛选、刷新、右侧列和表格内容都不可完整看到。若该后台明确只支持桌面，应定义最小宽度并提供横向滚动；否则需要把筛选区、汇总卡和双表改为纵向堆叠。

## 建议优先级

1. 先补统计口径说明：顶部汇总范围、组织行汇总规则、导出范围。
2. 调整组织行点击后的状态表达：把临时榜单范围放到右侧榜单区域，并提供清除入口。
3. 用户列补账号，降低重名误判。
4. 处理桌面空白和窄屏裁切：桌面降低左面板空白，窄屏至少提供最小宽度/横向滚动策略。

## 证据限制

1. 本次只基于当前静态原型截图和 DOM 文本审查，没有验证真实后端数据、导出文件内容和权限边界。
2. 截图无法完整证明键盘操作、屏幕阅读器朗读顺序和 tooltip 的可访问性，需要后续用键盘和辅助技术单独验证。
3. 本次未修改页面，只产出审查记录。
