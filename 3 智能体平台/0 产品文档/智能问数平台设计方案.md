# 交通工程建设管理公司：智能问数平台建设方案

## 第一部分：建设背景与目标

### 1.1 现状综述与挑战分析

#### 1.1.1 数字化建设成果回顾

经过 2023 至 2025 年的持续建设，公司已成功构建了稳固的数字化底座，形成了支撑业务运行的核心资产矩阵：

1. **全域数据底座初步建成**：依托数据治理工程，实现了工程建设、合同、资金、质量安全等核心领域的数据归集。
2. **专题库与视图体系完备**：构建了项目管理、履约管理、黑名单等专题板块，完成了公司级数据图谱搭建。
3. **多级感知体系运行稳定**：已建成覆盖“公司-指挥部-标段”的三级可视化看板，实现了业务 KPI 的图形化呈现。
4. **部位级质量溯源实现突破**：依托 **WBS（工程分解结构）编码**，打通了原材料、工艺、质检、资料的逻辑关联，实现了以“工程部位”为对象的全过程穿透管控。

#### 1.1.2 现状挑战：数字化消费的“末端梗阻”

虽然底座已完备，但在面向一线业务与决策管理层赋能时，仍存在显著的交互效能瓶颈：

1. **入口分散导致“人工转接”成本高**：各类业务专题看板缺乏横向关联。管理人员如需核对“计量支付”与“工序质量”的匹配度，需在多个系统间切换比对，缺乏一个“全域穿透、一语直达”的统一语义入口。
2. **固定模式难以响应“敏捷查询”**：现有看板多基于预设逻辑开发，属于“被动式”信息展示，难以灵活响应业务人员随机、非标准化的查询需求，海量数据资产与业务实战之间存在较高的“获取门槛”。
3. **交互范式与智能时代产生代差**：传统“层级菜单、表单填报”模式路径复杂，与新一代以智能体为核心的“对话即服务”交互范式相比效率低下，制约了数字化底座对实时监管的响应力。

## 1.2 建设驱动：弥合数据消费“最后一百米”

### 1.2.1 驱动数字化资产从“静态展示”向“敏捷服务”升维

智能问数平台旨在为现有资产安装“智能交互层”。不改变现有数据架构，通过大模型赋予系统“语义理解”能力，将分散的专题库转化为自然语言可交互的助手。这是实现数字化投入向实战提效转化的最优路径。

### 1.2.2 响应“穿透式”业务监管与精准提效需求

在交通工程领域，管理细节极细。智能问数平台通过自然语言技术，瞬间穿透复杂层级，直达底层逻辑。它能将“数字化看板”转化为“敏捷支撑力”，确保管理决策的快速响应。

### 1.2.3 降低全员使用门槛，构建数字化工作新范式

平台将充当各系统的“通用入口”，统一文档与数据检索。通过对话式交互，降低业务专家对 SQL 编写、复杂系统操作的依赖，真正实现“即问即答、辅助作业”。

## 1.3 建设目标与愿景

### 1.3.1 资产价值激活：让全业务数据“即时唤醒”

构建“机器听得懂、人说得习惯”的业务语义中枢。建立覆盖交通领域的**业务指标语义字典**，针对行业术语（如特定工艺简称）实现自然语言与底层逻辑的精准匹配，将沉淀的专题库转化为可实时唤醒的交互式服务。

### 1.3.2 管理多级赋能：构建“微观穿透”辅助体系

- **决策层：** 提供宏观经营指标及关键考核体系的敏捷查询。实现从“经营大盘”下钻至“具体 WBS 部位/构件级”明细（如即时调阅某墩身试验报告）的秒级穿透。
- **业务层：** 基于财务、合同、质量等数据库，为各职能处室构建专属助手。辅助人员快速进行业务逻辑校验（如基于 WBS 的质量溯源比对），显著提升管理效能。

### 1.3.3 交互范式变革：构建“零门槛”工作模式

构建简单直观的对话界面，消除多级菜单跳转与复杂报表查找。确保业务人员无需专业技术背景，即可实现对底层数据的“一语直达”，推动数字化办公向智能化全面演进。

## 第二部分：初步建设方案

### 2.1 存量赋能与架构平滑升级：保护既有数字化投资

#### 2.1.1 核心理念：驱动数字化资产从“静态存储”向“敏捷演进”

集成战略的核心在于保护既有数字化投资，通过将既有的业务数据资产重构为智能体的底层能力，实现数字化能力的平滑演进与资产增值：

- **知识库（业务记忆）**：不仅存储非结构化文档，更核心的是存入指标定义、业务规则及数据库表结构说明，建立业务语言与机器指令的对齐层。
- **MCP 工具集（业务技能）**：将现有业务系统（合同、质量、财务等）的 API 封装为标准工具，赋予智能体“按需调取系统功能”的能力。

#### 2.1.2 API 资源“工具化”：基于 MCP 实现系统跨域穿透

通过 **Model Context Protocol (MCP)** 协议，将现有的业务系统接口转化为智能体可直接调用的“工具箱”：

- **接口标准化封装**：利用 MJ-Core 的 MCP 管理能力，将已有的业务查询 API 封装为符合协议标准的 Tool。智能体根据用户意图，自主判定并执行对应的 API 调用。
- **能力即时复用**：直接复用已有的业务逻辑与权限控制体系，通过“对话即接口”的模式，大幅缩短用户获取业务结果的路径。

#### 2.1.3 业务逻辑“知识化”：构建全局业务语义对齐层

为解决大模型对特定业务口径理解偏差的问题，将核心业务逻辑注入知识库：

- **指标与规则入库**：将公司已沉淀的指标体系、计算公式、业务字典、WBS 编码逻辑作为核心知识上传。
- **逻辑检索增强（RAG）**：在生成查询指令前，智能体首先在“逻辑知识库”中检索相关的定义和规则，确保其理解的统计口径与公司管理要求完全一致。

#### 2.1.4 结构化数据“无缝映射”：专题数据库的深度集成

- **专题视图直接对接**：连接已有的数据中台专题数据库。利用智能体平台的数据问答能力，实现从自然语言到底层结构化查询的转化。
- **端到端查询闭环**：结合“业务逻辑知识”中定义的表结构说明，确保生成的查询指令符合公司内部的数据规范，实现对存量结构化资产的高效唤醒。

### 2.2 智能应用场景设计（按服务对象构建问数智能体）

针对交通工程建设管理公司不同层级的管理需求，拟构建以下三类核心问数智能体，实现全业务维度的智能交互：

#### 2.2.1 集团决策助手问数智能体

**功能定位**：作为决策层的一站式“数字顾问”，实现对集团宏观经营动态的敏捷调取与深度穿透。

- **核心场景**：汇聚现有的三级看板和集团 KPI 等各工程项目标段的关键指标数据。
- **应用深度**：支持“可问指标-关联明细-统计分析”的对话式穿透。不仅能即时回答“当前投资完成额”，还能自动关联“标段明细”并进行环比/同比的波动分析，辅助管理层实现“心中有数、决策有据”。

#### 2.2.2 项目指挥管理问数智能体

**功能定位**：遵循“一项目一智能体”原则，为各个指挥部提供专用的“管、控、辅”一体化的数据助手。

- **核心场景**：集成该项目内的项目管理数据（项目、标段、人员等数据）、工程质量数据（原材料、重点工艺、试验检测、监理旁站、质检资料等数据及相关预警闭合情况数据）。
- **应用深度**：聚焦现场管理颗粒度。指挥部人员可通过对话直接下钻至“具体部位”的质量风险点或预警指标，将原本沉淀在系统的静态数据转化为现场管控的实时驱动力。

#### 2.2.3 垂直处室助手：各业务专题问数智能体

**功能定位**：将前期为各职能处室建设的业务专题数据库，通过问数智能体转化为自然语言可交互的“对话式数据服务”。

- **核心应用**：通过数据中心目前已经聚合的专题数据库，为各业务条线提供专属的问数能力。
- **建设模式**：支持按需构建。根据处室职能划分，分别对接对应的专题库资源，实现专业数据的秒级调阅与闭环分析。

### 2.3 技术架构与核心功能

#### 2.3.1 总体架构设计（MJ-Core）

本平台采用 **MJ-Core 核心架构**，通过资源、能力、应用的三层解耦，支持高并发的语义解析与敏捷取数：

- **资源层**：统一纳管 MySQL、PostgreSQL 及国产神州通用数据库；集成多模态 LLM 及多种 Embedding/Rerank 模型服务。
- **MJ-Core 核心层**：内置 **Text-to-SQL 协同引擎**，通过 RAG（检索增强生成）与 ReAct 逻辑规划实现复杂业务意图的精准拆解。
- **展现层**：提供基于自然语言的对话界面，具备**智能可视化适配能力**，自动将查询结果转化为最优图表。

#### 2.3.2 核心功能模块：智能问答与可视化

- **智能问数（Smart Query）**：
  - **意图理解与 SQL 自动生成**：精准解析口语化需求，自动处理多表关联、聚合统计及跨库查询。
  - **自动执行与闭环分析**：自动执行 SQL 指令并获取结果，结合上下文进行智能总结分析。
  - **可视化智能选择**：根据返回数据的特征（如时间序列、数值占比），自动适配柱状图、折线图、饼图等可视化组件。
- **知识库问答（RAG App）**：
  - **智能切片预览**：支持在文档入库前进行切片效果实时预览，确保语义块的逻辑完整。
  - **召回测试沙箱**：内置召回评分与来源追溯体系，支持对切片质量进行持续优化。

#### 2.3.3 知识库治理与“取数优化”体系

针对交通工程领域的专业性，构建三级知识增强体系，显著提升取数准确率：

1. **黄金 SQL 模板库**：通过预定义 `{question}:{sql}` 映射范式，沉淀高频、复杂的标准查询逻辑，作为智能体的核心参考知识。
2. **业务口径知识库**：注入行业术语（如特定工艺简称）、业务计算口径及取数上下文，消除大模型对业务理解的偏差。
3. **元数据精细化管控**：支持对业务表、字段进行可见性设置与语义化标注。通过“移除冗余字段”与“补充字段描述”，优化大模型的上下文注意力，提升 SQL 生成质量。

#### 2.3.4 系统管理与基础资源配置

- **多源数据库集成**：支持业务数据库的快速连接配置，为智能问数应用提供实时/准实时数据源。
- **模型矩阵管理**：支持 LLM（负责 SQL 生成与总结）、Embedding（负责语义对齐）的组合配置，确保取数逻辑的严谨。
- **组织与权限同步**：支持对接钉钉、飞书等平台同步组织架构，实现基于角色的资源访问控制（RBAC），确保“敏感数据不越权”。

## 第三部分：安全与权限保障机制

### 3.1 基于“应用级硬隔离”的权限管控体系

平台权限设计遵循“**资源应用绑定、场景物理隔离**”的原则：

- **资源访问授权（API 级限制）**：数据库/API 与特定智能体应用强绑定，确保物理隔离。
- **用户访问准入（App-level RBAC）**：结合组织架构实现“人与智能体”的精准匹配。

### 3.2 安全审计与防护策略

- **全链路行为审计**：完整记录每位用户对智能体的提问、生成的 SQL 逻辑及返回结果，确保所有行为可追溯、可审计。

### 3.3 信创适配与国产化自主可控

平台深度适配交通行业信创环境，确保核心技术安全可控：

- **国产模型兼容性**：全面支持通义千问、DeepSeek等主流国产大模型，满足国企合规要求。
- **数据库信创支持**：深度适配达梦（Dameng）、人大金仓、神州通用等国产主流数据库系统。
- **全栈私有化部署**：支持全链路私有化环境部署，确保核心经营数据不出域，满足浙高建等大型国企的安全性要求。

## 第四部分：实施路线与预期成效

### 4.1 实施路径与节奏划分

本平台的建设将遵循“**分层实施、逐步覆盖、由总到分**”的策略，分三个阶段稳步推进：

1. **第一阶段：语义字典构建与决策助手上线**：
  - **语义层搭建**：完成集团核心 KPI、三级看板关键指标的语义映射，建立统一的业务逻辑字典。
  - **决策助手发布**：上线“集团决策助手智能体”，满足决策管理层对全集团经营大盘数据的即时查阅需求。
2. **第二阶段：职能处室接入与业务专题激活**：
  - **专题数据库挂载**：通过对接数据中心已有的专题数据库，为合同、财务、工程等垂直领域提供问数能力。
  - **处室应用推广**：实现各职能处室通过自然语言对专业指标与明细数据的快速检索与分析。
3. **第三阶段：项目级智能体全覆盖部署**：
  - **一项目一智能体**：落实对所有新开工项目的智能助手部署，集成项目基础档案及工程质量安全全过程数据。
  - **末端监管穿透**：实现从项目指挥部维度对施工末端、构件级质量安全风险的智能监控与预警。

### 4.2 预期成效与核心价值

- **效率跃升：从“人工跑数”到“秒级对话”**：
消除跨系统切换、手动汇总数据的冗余环节，将复杂业务查询的响应周期由原来的“小时级”压缩至“秒级”。
- **管理穿透：从“结果呈现”到“深度洞察”**：
实现从宏观经营大盘一键穿透至具体的部位级、构件级执行明细，辅助各级管理层即时识别业务偏差并下达指令。
- **资产激活：全面释放数字化底座的实战价值**：
通过智能体有效“唤醒”沉淀在数据中心专题库中的千万级资源，将既有的数字化投入转化为可见的生产力与管理效能。
